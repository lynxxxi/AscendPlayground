01 / VERDICT
Executive readout

它已经是一套生成服务子系统，不只是模型脚本集合

SGLang Diffusion 把多模态生成从离线 Pipeline 推进到可服务运行时：统一 CLI / API、模型注册与组件覆盖、Scheduler/Worker、优化后端、分布式并行、动态批处理，以及 Encoder→Denoiser→Decoder 分离式流水线。

强项

视觉生成优化面宽

从 kernel、attention、并行、offload、cache 到渐进分辨率和量化，且有逐模型兼容矩阵。

架构价值

Pipeline Stage 标准化

输入校验、编码、latent/timestep 准备、denoise、decode 被建模为阶段，并可声明角色归属。

边界

不是通用 any-to-any 编排器

当前核心仍是 diffusion 图像/视频生成。涉及多 AR LLM 的任意阶段图时，抽象范围与 vLLM-Omni 不同。

结论：若 AscendPlayground 的目标是建立高性能图像/长视频生成与服务基座，SGLang Diffusion 值得优先试点；若目标是语音对话、多个 AR/DiT 组件任意连接，则需额外评估主 SRT 与生成子系统的组合边界。
02 / POSITION
Repository boundary

SGLang 主运行时与 multimodal_gen 是相邻但不同的执行域

仓库中的 srt 主要负责本地语言模型运行，而 multimodal_gen 是加速图像/视频生成的推理框架。二者共享发布、CLI 和部分基础设施，但不能把 SRT 的所有 LLM 特性自动视为 diffusion 路径已具备。

03 / ARCH
Pipeline anatomy

标准生成流被拆成可归属角色的阶段

单体模式下所有阶段在一个服务内执行；分离式模式按 role_affinity 只实例化对应阶段，由无 GPU 的 DiffusionServer 负责控制路由，实际 tensor 通过 P2P 引擎在实例间直传。

Monolithic

默认模式，部署简单、无跨角色 tensor 传输，适合单机验证。

Disaggregated

Encoder、Denoiser、Decoder、Server 独立启动，可分别配置卡数与并行。

Direct transfer

控制消息经过 Server；大 tensor 由 Mooncake transfer engine P2P 直传并可使用 RDMA。

Independent replicas

每种角色可注册多个实例，并用空闲槽等策略调度，但需要真实负载验证平衡。

04 / OPT
Performance toolbox

先区分输出保持型优化与质量折中型优化

官方文档刻意使用 “output-preserving / lossless-style” 而非承诺 bit-exact；Kernel、设备和精度变化仍可带来细微数值差异。近似优化则明确可能改变 denoise 轨迹或生成结果。

PRESERVE

优先进入生产调优

  • speed / memory / manual performance mode
  • offload、FSDP、CFG parallel、sequence parallel
  • encoder parallel 与兼容请求动态批处理
  • attention backend 与 fused kernels
  • 组件常驻策略与合理的 stage placement
APPROXIMATE

必须绑定质量门禁

  • TeaCache / Cache-DiT 等跨步复用
  • 稀疏 attention：VSA、SLA、SVG2、Laser、BSA 等
  • FP8 / NVFP4 / GGUF 等低精度路径
  • 渐进分辨率、蒸馏与加速 LoRA
  • 任何改变 scheduler / denoise 轨迹的策略

06 / SERVE
Production interface

服务面已覆盖模型发现、图像、视频与 LoRA 管理

sglang serve 暴露 OpenAI-compatible Images / Videos API，并用 served-model-name 将公开模型身份与本地 checkpoint 路径解耦。服务端还提供健康检查、运行信息与分离式统计入口。

01 / DISCOVERGET /v1/models返回任务、卡数、精度和 Pipeline 信息。
02 / REQUESTImages / Videos文本、图片条件与模型采样参数。
03 / ADMITScheduler校验请求并聚合兼容 batch。
04 / EXECUTEPipelinemonolithic 或 disaggregated roles。
05 / MATERIALIZEArtifact图像 base64 / URL 或视频结果。
06 / OPERATELoRA / stats适配器管理、健康与队列指标。
API 语义：quality 选择模型拥有的采样级别（如 reference / validated accelerated path），而 output_quality 只控制文件压缩；二者不能混用。

08 / ROADMAP
Adoption plan

从单体、保持型优化，再走向近似与分离式

PHASE 0 / 1 周

选模型与冻结基线

图像选 Qwen-Image/Z-Image，视频优先 Wan2.1；固定尺寸、帧数、步数、seed、精度和版本。

EXIT → 单体离线输出可复现
PHASE 1 / 1–2 周

服务化与观测

打通 API、模型发现、队列、错误处理和端到端 profiling，标出 encoder/denoiser/decoder 占比。

EXIT → 并发服务稳定且瓶颈清楚
PHASE 2 / 2–4 周

保持型优化

按 profile 选择常驻、offload、attention、fusion、batching 与并行，不同时乱开所有开关。

EXIT → 收益可归因，质量门通过
PHASE 3 / 3–6 周

近似与分离式

先做 cache/低精度质量门，再依据阶段占比决定是否拆角色；以真实并发验证副本比。

EXIT → 生产 SLO 下收益覆盖复杂度
09 / RISKS
Decision ledger

最容易被误读的六件事

01

运行不等于优化兼容

模型 inventory 比逐项优化矩阵更广；没有勾选不代表不能跑，但代表不能声称已具备该加速路径。

02

平台支持不等于模型等价

同一命令在 CUDA 与 NPU 命中不同 kernel、dtype 与 fallback，必须以 profiler 判定。

03

动态批处理有兼容约束

不同 shape、步数、任务和条件输入不能自然合批；bucket 与等待窗口会改变尾延迟。

04

分离式部署并非免费

Denoiser 往往占绝大多数时间；若 Encoder/Decoder 很短，拆分主要改善资源利用而非单请求时延。

05

近似优化会叠加误差

cache、sparse、quant、distill 同开时必须测组合质量，不能用各自单项通过替代。

06

状态化世界模型更难

因果 cache、控制 token、会话重置和连续 rollout 让生命周期错误可能静默污染后续帧。
