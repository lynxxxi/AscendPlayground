MindIE-SD 编译工程图谱

setup.py 总调度 CANN custom OPP torch_npu plugin AscendC / AICPU / TIK

MindIE-SD 的构建不是单个 CMake target，而是 Python wheel、CANN custom OPP、torch_npu plugin 三个工程叠在一起。OPP 交给 CANN runtime 识别，plugin 交给 PyTorch dispatcher 调用。

一条构建主线

Python wheel

setup.py::CustomBuildPy 是总调度，先构建 native 产物，再打 Python 包。

  • 读取版本
  • 触发 ops/plugin
  • 合并 compile_commands

AscendC OPP

build_ascendc_ops.sh 配置 csrc/ops，生成 CANN custom op 包。

  • opapi
  • proto
  • tiling
  • kernel binary

AICPU / TIK

AICPU 先于 package 构建；TIK 使用 msopgen 临时工程。

  • CPU kernel so/json
  • TIK customize vendor

PyTorch plugin

build_plugin.sh 编译 libPTAExtensionOPS.so。

  • 注册 torch.ops
  • 分配 NPU 输出
  • 执行 ACLNN

Wheel 交付

把 mindiesd/ops/vendors 和 mindiesd/plugin 一起打入 wheel。

  • Python API
  • custom OPP
  • plugin so

torch_npu 与 CANN 暴露的接口

torch_npu / PyTorch

  • TORCH_LIBRARY 定义 torch.ops.mindiesd schema。
  • TORCH_LIBRARY_IMPL(..., PrivateUse1) 注册 NPU backend 实现。
  • TORCH_LIBRARY_IMPL(..., CatchAll) 处理 metadata 无 tensor 参数场景。
  • at_npu::native::empty_with_format 分配 NPU 输出并保留 format。
  • at_npu::native::get_npu_format 读取输入 tensor 的 NPU format。
  • c10_npu::getCurrentNPUStream 提供当前 stream 给 ACLNN。
  • at_npu::native::OpCommand 把 custom handler 纳入 torch_npu 执行。
  • torch_npu::utils::get_npu_device_type 构造无输入 tensor 时的 NPU options。

CANN / ACLNN / ACL

  • op_build 生成 ACLNN wrapper、proto、ops info。
  • ascendc_bin_param_build.py 生成 SOC 编译脚本。
  • parse_ini_to_json.py 生成 ops-info json。
  • ascendc_impl_build.py 生成 dynamic py。
  • aclCreateTensor 等接口把 ATen 参数转换成 ACL 参数。
  • aclnn*GetWorkspaceSize 是 ACLNN 第一段接口。
  • aclnn* 是 ACLNN 第二段执行接口。
  • libcust_opapi.so 是 custom ACLNN 符号所在地。

设计结论

MindIE-SD 的工程边界是清楚分层的：CANN 负责生成和识别 custom OPP，torch_npu 负责 PyTorch NPU dispatch 和 stream/format/tensor 管理，MindIE-SD plugin 负责把两者接起来。构建目标和产物名称大多不是随意命名，而是 CANN custom OPP 目录规范与 torch_npu extension 机制共同决定的。
