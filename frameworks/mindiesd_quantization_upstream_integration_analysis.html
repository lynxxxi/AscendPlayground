现有代码真正的问题

例如 W8A8QuantLinear.__init__ 通过 weights + prefix 自己取 tensor。上游框架已经加载并分片了权重，不能再让 MindIE 从文件取一次。

  • 保留 quant_matmul()。

@dataclass(frozen=True)
class W8A8State:
    weight: torch.Tensor
    weight_scale: torch.Tensor

class W8A8LinearRuntime:
    def prepare(self, weight, weight_scale, *, dtype, use_nz=False):
        # 从原 W8A8QuantLinear._init_dynamic_quant_param() 提取
        weight_scale = weight_scale.squeeze().to(dtype)
        if use_nz:
            weight = torch_npu.npu_format_cast(weight.npu(), 29).T
        else:
            weight = weight.T
        return W8A8State(weight=weight, weight_scale=weight_scale)

    def forward(self, x, state, bias=None, *, step_index=None):
        # 直接复用原 W8A8QuantLinear.quant_matmul() 主体
        original_shape = x.shape
        x = x.reshape(-1, x.shape[-1])
        qx, x_scale = torch_npu.npu_dynamic_quant(x)
        out = torch_npu.npu_quant_matmul(
            qx, state.weight, state.weight_scale,
            pertoken_scale=x_scale,
            bias=bias,
            output_dtype=x.dtype,
        )
        return out.reshape(*original_shape[:-1], -1)

class W8A8QuantLinear(nn.Module):
    def __init__(
        self, in_features, out_features,
        bias=True, weights=None, prefix=None, **kwargs
    ):
        super().__init__()
        tensors = {
            "weight": get_quant_weight(weights, f"{prefix}.weight"),
            "weight_scale": get_quant_weight(weights, f"{prefix}.weight_scale"),
        }
        loaded_bias = (
            get_quant_weight(weights, f"{prefix}.bias") if bias else None
        )
        self.register_buffer("bias", loaded_bias, persistent=False)
        self.runtime = W8A8LinearRuntime()
        self.state = self.runtime.prepare(
            tensors["weight"], tensors["weight_scale"],
            dtype=kwargs.get("dtype", torch.bfloat16),
            use_nz=kwargs.get("use_nz", False),
        )

    def forward(self, x):
        return self.runtime.forward(x, self.state, self.bias)

# [现有 NPU 特化类，不新增]
class NPUMxfp8LinearMethod(MXFPLinearMethodBase):
    # [现有方法：修改] 直接实例化对应的具体 runtime 类
    def __init__(self, quant_config):
        # 放在 NPU 类内部，避免非 NPU 平台导入 MindIE
        from mindiesd.layers.quant_linear import (
            MXFP8LinearRuntime,
            MXFP8OnlineLinearRuntime,
        )
        self.quant_config = quant_config
        self.out_dtype = torch.get_default_dtype()
        runtime_cls = (
            MXFP8LinearRuntime
            if quant_config.is_checkpoint_mxfp8_serialized
            else MXFP8OnlineLinearRuntime
        )
        self._mindie_runtime = runtime_cls()

    # [现有重写：原样保留] weight / weight_scale 参数注册与 loader
    def create_weights(self, layer, *args, **kwargs):
        ...  # 保留当前方法体

    # [新增私有方法] offline/online 子类共用
    def _prepare_runtime(self, layer):
        tensors = {"weight": layer.weight.data}
        if hasattr(layer, "weight_scale"):
            tensors["weight_scale"] = layer.weight_scale.data
        layer._mindie_state = self._mindie_runtime.prepare(
            **tensors, dtype=self.out_dtype
        )
        layer._already_called_process_weights_after_loading = True

    # [现有重写：修改] 直接准备 runtime state
    def process_weights_after_loading(self, layer):
        self._prepare_runtime(layer)

    # [新增标准 hook 重写] 不重写基类 apply，保留其 reshape/unreshape 骨架
    def _apply_inner(self, layer, x, bias, ori_dtype):
        return self._mindie_runtime.forward(
            x, layer._mindie_state, bias=bias
        )

# [现有子类，不新增]
class NPUMxfp8OnlineLinearMethod(_LazyWeightMixin, NPUMxfp8LinearMethod):
    # [现有重写：修改] online 类覆盖了该 hook，直接准备 state
    def process_weights_after_loading(self, layer):
        self._prepare_runtime(layer)
对象性质怎么改
DiffusionMXFP8Config现有，完全保留不新增 MindIE config，不增加 registry 或用户配置。
NPUMxfp8LinearMethod现有类修改 __init__/process_weights_after_loading；新增私有 _prepare_runtime 与标准 hook _apply_inner。
NPUMxfp8OnlineLinearMethod现有类现有 process_weights_after_loading 直接调用同一 prepare helper。
NPUInt8LinearMethod / MXFP4 类现有类同样按具体 runtime 类直接修改现有 prepare/apply hook。
MindIERuntimeConfig不新增MindIE 是 NPU 实现提供者，不是新的量化算法或 checkpoint 类型。
为什么放在 Ascend/NPU 特化类里：正因为已经有这些类，而且 GPU/XPU 各自也有 method。NPU 类直接 import MindIE 的具体 runtime，既能收口复制代码，又不会让 CUDA、ROCm、XPU import MindIE；中间不需要 provider config、API facade 或 registry。

06 / 为什么这样改
Community fit & platform boundary

算法配置统一，设备实现特化

用户选择的是 MXFP8/MXFP4/INT8 算法，不是选择 MindIE 供应商。框架 config 保持统一，再由平台分发到 NPU/GPU/XPU method；MindIE 只藏在 Ascend/NPU method 内部。

07 / 怎么落地
PR order & tests

先做 MXFP8 单路径，再横向扩算法

第一阶段就让上游 NPU 类只调用 MindIE runtime，并删除对应的复制执行主体。旧提交或固定输出作为数值基线，不在生产代码里保留第二条执行路径。

在现有目录加入两个 runtime 文件

layers/quant_linear.py 实现量化 Linear，layers/flash_attn/quant_flash_attn.py 实现量化 FA；不新增文件夹、API 层或 registry。

现有 NPU 类直接调用

SGLang 和 Omni 各先接 MXFP8 online；按具体类名 import，不用算法字符串查找，同时删除对应的本地 prepare/matmul 复制主体。

对照旧基线验证

以修改前提交的固定输入输出为基线，验证 TP=1/2、CPU offload、多 step、并发和整段 latent trajectory。

按具体类扩算法

依次接入 INT8、MXFP4、DualScale、MoE 与量化 FA；每种算法都是直接 import 对应 runtime，不增加统一分发层。

Import

仅 Ascend/NPU 文件精确 import 所需的 MindIE runtime 类/函数；不拉入 graph rewrite 模块，也不污染 GPU 路径。

Numerics

同一 tensor 对比修改前固定基线、MindIE runtime 与端到端输出。

Parallel

Row/Column/QKV Linear 在分片后 prepare，不能再次切分或转置错误。

Concurrency

交错执行不同 step，请求结果必须等于逐请求串行结果。

首个可合入版本：仍建议选择 MXFP8 online Linear，但命令行和模型配置继续写现有 mxfp8。是否命中 MindIE 只出现在日志/指标里，不成为用户需要理解的新概念。
