01 / VERDICT
Executive decision

移植“量化方法”，不要移植“改图框架”

MindIE SD 的低精度 kernel 与 diffusion 策略有上游价值，但当前 quantize(model) 在模型构造后遍历 nn.Linear、删除参数并替换模块，这与上游的 TP 分片、meta-device、FSDP/HSDP 和严格权重加载生命周期相冲突。

推荐：共享低层 NPU 能力，分别实现上游原生 QuantMethod 适配器。

Linear/MoE 进入上游现有的 create_weights → load shard → process_weights_after_loading → apply 生命周期；FA 量化进入 attention backend；timestep 策略进入请求/批次上下文。MindIE SD 保留算法参考实现和 kernel 资产，但不再拥有上游模型图。

02 / SCOPE
Scope & evidence

分析口径：以代码路径为准，不把“平台支持”当成“组合可用”

报告以本地源码快照为主、官方文档为交叉证据。所谓“支持”拆成算法、checkpoint、layer、模型、硬件代际、并行方式、编译模式七个维度。

研究对象

MindIE SD 的 quantization/{config,mode,quantize,layer}.py、FA 自定义算子；SGLang SRT 与 multimodal_gen；vLLM core、vLLM-Ascend、vLLM-Omni diffusion。

功能范围

离线/在线权重量化、动态/静态激活、混合精度、timestep 切换、量化 FA、MoE、权重映射与后处理。

证据等级

代码已存在、文档声明/待矩阵验证、建议设计/推断分开标注；性能数字不跨模型、shape 与硬件外推。

参数生命周期不兼容

量化层把 safetensors 直接读成 persistent=False buffer；上游需要 Parameter 属性承载 input/output dim、shard id 与 weight loader。

模型类型匹配过窄

后处理只识别 nn.Linear，无法自然覆盖 Column/Row/QKV/Merged Linear、MoE expert 和上游 fused layer。

算法描述与执行混合

QuantMode bit flag 主要用于分派，W4A4 仍借用 smooth-quant 标志；不适合作为跨框架稳定 schema。

并发上下文不安全

timestep 由全局 TimestepManager 获取；连续批处理中不同请求、不同 step 可能共享一个 worker。

Attention 依赖隐式注入

add_fa_quant 只挂载 layer.fa_quant；目标模型 forward 是否调用它仍由模型魔改决定。

硬件失败太晚

部分能力直到 torch_npu op 调用或 shape 转换才报错；上游需要启动期 capability negotiation，禁止 silent fallback。

边界 01
谁拥有模型图

永远由上游框架拥有。MindIE 适配器返回方法对象，不替换 SGLang/vLLM 的并行 Linear，不接管模型类构造，也不绕开官方 loader。

边界 02
谁拥有 checkpoint

checkpoint 是生产者与 runtime 之间的版本化 ABI。msModelSlim 原始输出可保留，但必须提供 manifest/转换器把名称、scale 与 fallback 映射到上游 runtime prefix。

边界 03
谁拥有 step

diffusion scheduler/engine 拥有 step；量化方法只消费上下文。若一个 batch 含不同 step，策略必须支持逐样本或在 scheduler 层按 quant policy 分桶。

边界 04
谁决定 fallback

配置与 capability resolver 共同决定，并在启动时冻结执行计划。运行中仅允许预声明的 FLOAT/FP8/W4A8 切换；任何未声明回退都计入错误与指标。

06 / CONTRACT
Native method lifecycle

MindIE Layer 如何拆进上游四个钩子

核心变化是把“一个自给自足的 QuantLinear 类”拆成“框架 Linear 上的一组参数与方法”。这让权重分片、QKV 融合、CPU offload 和 meta-device 都能继续工作。

08 / ADAPTERS
Framework-specific plan

两个上游需要两套薄适配器，不需要两套 kernel

上游的 parallel layer、loader 与 runtime context 不同，适配层不能强行共用；真正应该共用的是算法 schema、weight transform、op wrapper 与黄金向量。

SGLANG

短期：分别落 SRT 与 multimodal_gen

  • SRT 继续使用 ModelSlimConfig → ModelSlimLinearMethod → scheme，平台通过 get_quantization_config 覆盖硬件实现。
  • diffusion 继续由 TransformerQuantLoadSpec 解析 config/safetensors，再把 quant_config 传入 DiT 的 parallel Linear。
  • 把 multimodal_gen 内引用 SRT scheme 的边界收敛为稳定共享包，避免反向跨子系统导入完整 SRT runtime。
  • 每个 DiT 模型必须声明 packed_modules_mapping 和 checkpoint→runtime WeightsMapper。
  • Attention 走 multimodal_gen backend registry；不要塞进 Linear registry。
VLLM / OMNI

优先利用官方 OOT 注册与 component 路由

  • vLLM core 通过 @register_quantization_config 支持 OOT 方法；NPU 算法优先驻留 vLLM-Ascend 插件。
  • vLLM-Omni 的 factory 只提供 diffusion 特有 override，能复用 core/Ascend 的就不要 fork。
  • ComponentQuantizationConfig 负责 transformer / text_encoder / VAE / stage 作用域，不把 BF16 组件错误套上预量化 method。
  • DiffusersLoader 必须保留 layerwise meta materialization、postprocess 幂等标志与 CPU offload 规则。
  • 每个 stage 自己解析磁盘 quantization_config；cascade 的 transformer 与 transformer_2 可有不同 fallback。

不可只看类名

QKV、gate/up 与 expert 可能在 runtime 融合。checkpoint 的三个 scale 是否允许合并，必须由 scheme 显式验证；“部分 shard BF16”应启动失败。

不可只看 prefix

prefix 要经过 model-owned mapper。字符串 replace 只能作为模型适配器，不应散落在通用量化配置里。

不可静默回 BF16

请求指定量化但模型漏传 quant_config、op 不存在或 shape 不兼容时应 fail fast；只有 manifest 声明的 fallback 才可执行。

09 / ABI
Checkpoint contract

把 quant_model_description.json 从“字典”升级为版本化 manifest

当前 JSON 主要是参数名到算法字符串的映射，runtime 仍要从文件名、dtype 和代码约定反推 scale 语义。上游稳定接入需要自描述且可前置校验的 schema。

{ "format": "ascend.quant.v1", "producer": {"name": "msmodelslim", "version": "x.y"}, "target": {"soc": ["A2", "A3"], "cann_min": "..."}, "components": { "transformer": { "name_space": "diffusers", "runtime_mapper": "wan22_v1", "layers": { "blocks.0.ffn.proj": { "algorithm": "W4A4_MXFP4_DUALSCALE", "weight": {"dtype": "fp4_e2m1x2", "layout": "ND"}, "scales": [ {"name": "weight_scale", "granularity": "K:32", "dtype": "e8m0"}, {"name": "weight_dual_scale", "granularity": "K:512", "dtype": "fp32"}, {"name": "mul_scale", "granularity": "input_channel", "dtype": "fp32"} ] } }, "fallback": {"layers": ["blocks.0.*"], "precision": "bf16"} } } }

名称

声明 checkpoint namespace 与 mapper id；映射器由模型所有并可版本化。

布局

磁盘 layout 与 runtime layout 分开；NZ 是加载后设备布局，不应伪装成 checkpoint dtype。

分片

每个 tensor 声明 sharding axis；scale 的分片轴可能不同于 weight。

兼容

未知 format major、缺 tensor、部分 fused shard、online/offline 错配均在模型加载前失败。

10 / FA + STEP
Diffusion-specific design

FA 量化与 timestep 是接入难点，不是 Linear 的附属参数

Linear 量化可以按 layer prefix 静态选 method；FA 的 Q/K/V 是运行时 tensor，timestep 又随请求推进。二者需要 attention backend 与 scheduler 共同参与。

量化 AttentionBackend 契约

  • 输入：Q/K/V、layout、mask、scale、sequence metadata、可选 rotation。
  • 能力：FP8/MXFP8/MXFP4、BNSD/BSND、varlen、SP/ring、torch.compile。
  • 选择：启动期按 SoC/CANN/op/shape 决定候选；每次调用只做轻量 dispatch。
  • 交付：ACLNN 后端与 MindIE custom-op 后端分开，custom op 缺失时只允许显式策略 fallback。
  • 观测：记录 chosen backend、quant mode、fallback count 与 padding overhead。

请求级 StepQuantPolicy

  • 由 scheduler 把 step_index、sigma/timestep 与 policy id 放入 forward context。
  • 策略是纯函数：(layer, step, shape) → W4A4 | W4A8 | FP8 | FLOAT。
  • 同一 batch 策略不同时：优先按 mode 分桶；不支持逐样本 kernel 时禁止混跑。
  • torch.compile 图按有限 mode/shape 建缓存，避免把任意 Python 字典捕获进图。
  • 取消、重试和 stage 解耦必须携带 step/policy，不能读取 worker 全局变量。
关于 rotation：离线校准的 q_rot/k_rot 与在线生成 Hadamard rotation 不是等价 checkpoint。manifest 必须标注 rotation 来源、seed、head_dim 与应用顺序；模型 fusion 若改变 Q/K head 排布，rotation 也必须跟随重排。
11 / ADR
Decision ledger

五项关键架构决策

以下 ADR 建议作为实施前的评审基线；状态均为 Proposed，需由 MindIE、SGLang 与 vLLM-Ascend/Omni 维护者共同确认。

ADR-001
PROPOSED
框架拥有 Layer，MindIE 提供 kernel/backend。

正向：兼容并行、loader、LoRA、compile；负向：需要为两个上游写薄适配器。拒绝方案：直接复用 MindIE QuantLinear 或运行后改图。

ADR-002
PROPOSED
checkpoint manifest 是版本化公共 ABI。

正向：生产者与 runtime 解耦、可 fail-fast；负向：msModelSlim 导出和旧 checkpoint 需要转换。兼容期保留 legacy JSON reader，但只输出标准内部 spec。

ADR-003
PROPOSED
上游原生注册优先，平台插件承载硬件实现。

vLLM 使用官方 OOT quant registry/vLLM-Ascend；SGLang 使用 platform override 和现有 registry。拒绝在 model 文件里硬编码 torch_npu 分支。

ADR-004
PROPOSED
FA 量化从 LinearQuantizationConfig 分离。

可在顶层 QuantPlan 中组合 linear 与 attention 子计划，但执行时分别走 LinearMethod 与 AttentionBackend；避免让 checkpoint weight scheme 决定所有运行时 attention 行为。

ADR-005
PROPOSED
禁止未声明的精度回退。

op、shape 或硬件不满足时启动失败；仅 manifest/policy 中明确的 BF16/FP8/W4A8 fallback 可执行，并暴露指标。代价是首次接入更严格，收益是消除“看似量化、实际浮点”。

12 / ROADMAP
Upstream delivery plan

五阶段交付：先 ABI 和 Linear，再碰 FA 与动态策略

每阶段都能独立合入与回滚。时间是具备目标 NPU、现成量化权重和两名熟悉上游的工程师时的粗估，不含算法重新校准。

PHASE 0 · 1–2 周

冻结基线与 ABI

选 Wan2.2 单 Transformer + cascade 各一；冻结 CANN/torch_npu、上游 commit、BF16 基线、旧/新 checkpoint 样本。实现 legacy JSON → QuantCheckpointSpec 校验器。

EXIT → 错配在分配 NPU 大内存前失败
PHASE 1 · 2–4 周

Linear P0

W8A8 dynamic/static、MXFP8、MXFP4 single/DualScale 进入原生 LinearMethod；打通 Replicated/Column/Row/QKV/Merged 与 TP=1/2。

EXIT → 权重覆盖 100%，无 post-hoc graph rewrite
PHASE 2 · 2–3 周

Loader 与组件化

补齐 online/offline、meta-device、CPU offload、FSDP/HSDP、cascade component config、name mapper 与 strict load；合并重复转换工具。

EXIT → component/stage 可独立量化与回退
PHASE 3 · 3–5 周

FA backend

先 FP8/MXFP8 ACLNN，再独立发布 MXFP4 custom op；覆盖 layout、varlen、mask、SP/ring，接入 compile fake/meta。

EXIT → backend 选择可观测，禁止 silent fallback
PHASE 4 · 3–5 周

Step policy + MoE

把 TimestepManager 改成 request/batch context；按 mode 分桶；接入 MoE runner 与多 stage；建立长稳和性能门禁。

EXIT → 连续批处理下跨请求无状态污染
PR 拆分建议：schema/validator、每个算法 scheme、每种 parallel Linear、loader integration、attention backend、custom-op package、timestep context、模型 recipe、CI matrix 分开提交。不要把模型接入、kernel、新 checkpoint 格式和调度重构塞进一个巨型 PR。

14 / RISKS
Failure modes

最可能让“能跑”变成“不能交付”的风险

R1 · HIGH

权重名即隐形 ABI

Diffusers、msModelSlim 与 runtime fusion 名称不同。缓解：model-owned mapper + manifest mapper version + strict coverage。

R2 · HIGH

scale 分片错轴

weight、fine scale、coarse scale、mul_scale 的 TP 轴不同。缓解：tensor spec 声明 shard axis，单独测试 Row/Column。

R3 · HIGH

step 状态串请求

全局 manager 在异步/连续批处理下污染结果。缓解：context 显式传递，策略分桶与并发回归。

R4 · MED

在线/离线语义混淆

DualScale offline 有 calibrated mul_scale，online 没有。缓解：serialized flag + tensor presence + mode mismatch fail-fast。

R5 · MED

自定义 op ABI 漂移

PyTorch、CANN、torch_npu 与 op schema 组合变化。缓解：独立 wheel、版本握手、fake/meta、兼容矩阵和 import-time probe。

R6 · MED

优化组合非交换

量化与 QKV fusion、LoRA、offload、SP/ring、compile 组合可能改变布局或误差。缓解：按组合验收，不从单项通过推导组合通过。

R7 · OPS

两上游版本漂移

vLLM/SGLang method 与 loader 接口频繁演进。缓解：薄 adapter、受控版本窗口、每月 rebase CI。

R8 · QUALITY

只看最终图片

最终像素可能掩盖中途爆炸或偶然收敛。缓解：latent trajectory、敏感层输出与语义指标联合门禁。

R9 · LICENSE

代码搬运边界

MindIE SD 为 Mulan PSL v2，上游多为 Apache-2.0。缓解：法务确认；优先重写适配器、保留来源与许可证头。
