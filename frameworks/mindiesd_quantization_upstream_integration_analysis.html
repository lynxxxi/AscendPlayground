01 / 先说结论
What to change

不加 MindIE 特化 config；改现有 Ascend/NPU 类

你说的收口方式更符合现状：已有 NPU 量化逻辑本来就是从 MindIE 挪过去的。现在只需在现有特化类内部探测 MindIE；可用则委托 runtime，不可用则继续走当前本地实现。

保留现有 mxfp8 / mxfp4 / int8 配置与类名；只改方法体，不新增 mindie_runtime 量化类型。

这和 vLLM-Omni 的 FA、RoPE、LayerNorm 先例一致：NPU 特化实现里检查 MindIE 能力，存在则调用 MindIE，不存在或版本不具备新接口则走 native fallback。

from dataclasses import dataclass
from typing import Mapping, Protocol
import torch

@dataclass(frozen=True)
class RuntimeContext:
    step_index: int | None = None

@dataclass(frozen=True)
class LinearMeta:
    algorithm: str          # "w8a8", "mxfp8", "mxfp4" ...
    input_size: int
    output_size: int
    dtype: torch.dtype
    use_nz: bool = False

class QuantLinearRuntime(Protocol):
    def prepare(
        self, tensors: Mapping[str, torch.Tensor], meta: LinearMeta
    ) -> object: ...

    def forward(
        self, x: torch.Tensor, state: object,
        bias: torch.Tensor | None = None,
        context: RuntimeContext | None = None,
    ) -> torch.Tensor: ...
mindiesd/runtime_quant/linear.pyW8A8 示例
@dataclass(frozen=True)
class W8A8State:
    weight: torch.Tensor
    weight_scale: torch.Tensor

class W8A8Runtime:
    def prepare(self, tensors, meta):
        # 从原 W8A8QuantLinear._init_dynamic_quant_param() 提取
        weight = tensors["weight"]
        weight_scale = tensors["weight_scale"].squeeze().to(meta.dtype)
        if meta.use_nz:
            weight = torch_npu.npu_format_cast(weight.npu(), 29).T
        else:
            weight = weight.T
        return W8A8State(weight=weight, weight_scale=weight_scale)

    def forward(self, x, state, bias=None, context=None):
        # 直接复用原 W8A8QuantLinear.quant_matmul() 主体
        original_shape = x.shape
        x = x.reshape(-1, x.shape[-1])
        qx, x_scale = torch_npu.npu_dynamic_quant(x)
        out = torch_npu.npu_quant_matmul(
            qx, state.weight, state.weight_scale,
            pertoken_scale=x_scale,
            bias=bias,
            output_dtype=x.dtype,
        )
        return out.reshape(*original_shape[:-1], -1)

def create_linear_runtime(algorithm: str) -> QuantLinearRuntime:
    return {
        "w8a8": W8A8Runtime,
        "mxfp8": MXFP8Runtime,

        "mxfp4": MXFP4Runtime,
        "mxfp4_dualscale": MXFP4DualScaleRuntime,
    }[algorithm]()

class W8A8QuantLinear(nn.Module):
    def __init__(
        self, in_features, out_features,
        bias=True, weights=None, prefix=None, **kwargs
    ):
        super().__init__()
        tensors = {
            "weight": get_quant_weight(weights, f"{prefix}.weight"),
            "weight_scale": get_quant_weight(weights, f"{prefix}.weight_scale"),
        }
        loaded_bias = (
            get_quant_weight(weights, f"{prefix}.bias") if bias else None
        )
        self.register_buffer("bias", loaded_bias, persistent=False)
        self.runtime = W8A8Runtime()
        self.state = self.runtime.prepare(
            tensors,
            LinearMeta(
                algorithm="w8a8",
                input_size=in_features,
                output_size=out_features,
                dtype=kwargs.get("dtype", torch.bfloat16),
                use_nz=kwargs.get("use_nz", False),
            ),
        )

    def forward(self, x):
        return self.runtime.forward(x, self.state, self.bias)

from importlib.util import find_spec

# [新增私有 helper] 只做能力探测；不改变公开配置。
def _try_create_mindie_runtime(algorithm: str):
    if find_spec("mindiesd") is None:
        return None
    try:
        from mindiesd.runtime_quant import create_linear_runtime
        return create_linear_runtime(algorithm)
    except (ImportError, AttributeError, KeyError) as exc:
        logger.warning_once(
            "MindIE 已安装但不具备 %s runtime，使用现有 NPU fallback：%s",
            algorithm, exc,
        )
        return None

对象性质怎么改
DiffusionMXFP8Config现有，完全保留不新增 MindIE config，不修改 registry 或用户配置。
NPUMxfp8LinearMethod现有类修改 __init__/process_weights_after_loading；新增私有 _prepare_with_mindie 与标准 hook _apply_inner。
NPUMxfp8OnlineLinearMethod现有类给现有 process_weights_after_loading 加 MindIE 提前返回。
NPUInt8LinearMethod / MXFP4 类现有类同样修改现有 prepare/apply hook；fallback 暂时保留。
MindIERuntimeConfig不新增MindIE 是 NPU 实现提供者，不是新的量化算法或 checkpoint 类型。
为什么放在 Ascend/NPU 特化类里：正因为已经有这些类，而且 GPU/XPU 各自也有 method。把可选依赖探测放在 NPU 类内部，既能收口复制代码，又不会让 CUDA、ROCm、XPU import MindIE；这比新增 provider 专用 config 更符合当前分发结构。

Community fit & platform boundary

用户选择的是 MXFP8/MXFP4/INT8 算法，不是选择 MindIE 供应商。框架 config 保持统一，再由平台分发到 NPU/GPU/XPU method；MindIE 只藏在 Ascend/NPU method 内部。

07 / 怎么落地
PR order & tests

先双路径收口，再删除复制代码

第一阶段不删当前上游 NPU 主体，它正好是兼容 fallback 和数值基线；确认 MindIE runtime 稳定后，再把复制实现从两个上游移除。

MindIE 提供稳定 runtime API

新增 tensor 输入的 prepare/forward，导出算法能力查询；旧 layer 内部复用它，保证 MindIE 自身兼容。

现有 NPU 类加入可选委托

SGLang 和 Omni 各先接 MXFP8 online；不改 config/registry。用环境开关仅做测试强制 fallback，不作为长期用户配置。

双路径比对与观测

记录 mindie_runtime/local_fallback 命中，验证 TP=1/2、CPU offload、多 step、并发和整段 latent trajectory。

扩算法并删除复制主体

迁移 INT8、MXFP4、DualScale、MoE 与量化 FA。连续两个版本稳定后删除本地 fallback，只保留清晰的缺依赖报错。

Import

仅 Ascend/NPU 文件可选 import MindIE runtime；不拉入 graph rewrite 模块，也不污染 GPU 路径。

Numerics

同一 tensor 对比 MindIE runtime、两个上游现有 NPU fallback 与端到端输出。

Parallel

Row/Column/QKV Linear 在分片后 prepare，不能再次切分或转置错误。

Concurrency

交错执行不同 step，请求结果必须等于逐请求串行结果。

首个可合入版本：仍建议选择 MXFP8 online Linear，但命令行和模型配置继续写现有 mxfp8。是否命中 MindIE 只出现在日志/指标里，不成为用户需要理解的新概念。
