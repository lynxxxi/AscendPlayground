minWM 技术与
加速需求分析

以 Wan 2.2 为主流视频生成基线，分析 minWM 如何把双向视频扩散底座转化为低延迟、可交互、可持续滚动的世界模型，以及这一变化为何重新定义了加速优先级。

基于论文 + 官方仓库源码重点：推理时延 / KV cache / 并行 / 量化 / VAE面向：昇腾适配与框架规划

先说结论

minWM 和 Wan 2.2 不是同一层级的竞品。前者是“世界模型改造流水线”，后者是“高质量离线视频生成底座”。

定位
框架，不是单模型

把现有 T2V/TI2V 底座改造成带相机控制的少步自回归世界模型。

算法级主加速
50 → 4 步

通过 Causal Forcing / CF++ 与非对称 DMD，把多步扩散蒸馏为 4-step AR；CF++ 通用视频实验已验证 1–2 step，但动作模型尚未开放该路径。

公开实测 · 单 A800
236.64×

Wan2.1-1.3B 的首帧延迟从 269.055 s 降至 1.137 s；不含 VAE。

最优先工程目标
稳定实时，而非吞吐

首帧、逐块尾延迟和长时显存必须有界；仅提升离线 clips/hour 不够。

核心判断：Wan 2.2 的优化中心是“大模型 × 长序列 × 多去噪步”的离线吞吐；minWM 的优化中心则是“短固定块 × 少步 × 有状态缓存”的交互尾延迟。对 minWM，步数蒸馏、因果注意力、滚动 KV、VAE 流水化与消除 CFG 双前向是 P0/P1；通用 DiT step-cache、模型 offload 和复杂 MoE 调度优先级反而下降。

minWM 到底用了什么技术

两阶段、四个训练节点，把“看完整段再生成”的双向模型改成“只看历史、边交互边生成”的因果模型。

视频底座Wan2.1 1.3B（Cross-Attn DiT）或 HY1.5 8B（MMDiT）
相机数据重建/重渲染或 WorldPlay 合成，强调准确轨迹
PRoPE SFT将内参 K 与 SE(3) 外参注入自注意力
Teacher Forcing因果 mask；干净历史 + 带噪当前块，获得 AR 能力
ODE / Causal CD把多步 AR 初始化为少步 AR；CD 避免离线轨迹
Asym. DMD学生自滚动；双向教师作 real score，在线 fake score
流式推理4 latent-frame/chunk、4 steps、因果 KV cache、相机动作

PRoPE：几何条件进入注意力

不是把动作简单拼到 latent 上。PRoPE 用投影矩阵把相机内外参转化为 token 间的相对射影变换，因此保留原有生成结构，同时让空间 token 感知相机运动。

加速含义：需要支持 Q/K/V 前后的结构化变换与 RoPE 融合，避免大量小算子和 layout 往返。

Causal Forcing：训练—推理对齐

先用真实历史做 teacher forcing，再让少步学生 self-rollout，并由高质量双向教师做非对称分布匹配，缓解 AR 暴露偏差与误差累积。

加速含义：训练态同时存在 student、real-score、fake-score/EMA，显存和通信压力明显高于普通 SFT。

Chunk-wise AR：交互粒度

论文实验生成 480×832、77 帧，AR 块大小为 4 个 latent frames。块内并行去噪，块间严格因果，首块可先交付。

加速含义：固定 chunk 有利于静态图；长时上下文则要求 KV 生命周期与窗口策略独立设计。

代码成熟度提示：论文/README 主路径是 4-step chunk-wise。2026-06-15 的仓库 HEAD 已可见 HY 路线文本与视觉 KV cache，但通过 torch.cat 逐块扩展视觉 KV；README 仍将更广义“inference acceleration”标为 TBD。故“有 KV cache”不等于“已有生产级、长时有界的 rolling/paged KV”。

比较重点不是画质榜单，而是工作负载怎样改变了硬件与框架的优化目标。

训练侧：昂贵的不只是模型

minWM 的训练是多阶段系统工程。能否复现，往往由数据质量、有效 batch 和多模型驻留共同决定。

相机数据是第一瓶颈

论文中，直接使用估计相机位姿的 SpatialVid 未获得可靠控制；重建后重渲染或 WorldPlay 生成的“近似真值”轨迹才有效。

优先级：高于盲目扩大训练 FLOPs

有效 batch 不能过小

Wan2.1 实验中 batch<4 常失败，batch 8 仍不稳定，batch 16 可完成高控制性训练；这直接要求 DP/梯度累积设计。

建议：固定有效 batch，再选择 SP 与 DP

Causal CD 优于离线 ODE

CF++ 用在线相邻 ODE 单步监督替代完整 PF-ODE 轨迹。其论文报告 Stage 2 训练成本约降 4×，并消除约 1.9 TiB 额外轨迹存储。

建议：新平台优先支持 CD 路线

DMD 多模型显存峰值

student self-rollout + frozen real score + online fake score/EMA，使 DMD 比普通 SFT 更需要 FSDP、BF16、激活重算和通信/计算重叠。

仓库已有 FSDP、SP、BF16、gradient checkpoint 基础

面向昇腾的落地路线

建议先打通 Wan2.1-1.3B 的确定性低延迟路径，再扩到 HY1.5-8B；先建立端到端基准，再追求单算子峰值。

目标执行拓扑

  • CPU 控制线程：接收 WASD/相机轨迹，提前生成下一块 PRoPE 参数。
  • NPU Stream A：4-step causal DiT，读只增/滚动 KV。
  • NPU Stream B：上一块 VAE decode 与后处理。
  • 输出线程：按帧显示/编码，向推理端提供背压。
  • 会话状态：KV 页、RoPE offset、随机状态、动作时间戳显式管理。
关键约束：把“首帧”定义为用户真正看到的第一帧，必须包含文本/图像预处理、DiT、VAE、设备同步和传输；论文表格排除了 VAE，只能作为 DiT 算法对比。

P0 · 建立正确基线

BF16、batch=1、guidance=1、480×832、77 帧、chunk=4、steps=4；拆分 text/PRoPE、DiT、KV append、VAE、H2D/D2H 时间。用 1/10/100 个 chunk 测显存和 P50/P95/P99。

P0 · 改造注意力与 KV

实现支持历史 KV + 当前 QKV 的 causal fused attention；KV 预分配为页/环形区，append 原地写入，禁止热路径 cat。为 CFG=1 走单缓存快路径。

P0 · 固定图与流水

固化 chunk、head、hidden、resolution；把 4 个 timestep、调度器更新与 PRoPE 融入图或图外常量。DiT(n+1) 与 VAE(n) 双流重叠。

P1 · 精度与多卡

先量化 linear/MLP，再 QKV/out projection，最后考虑 KV；敏感层保留 BF16。高分辨率/8B 使用 USP/序列并行，并以交互延迟决定并行度。

P1 · 长时稳定

加入固定历史窗口、稀疏锚帧或记忆压缩；同时评测场景身份、几何、动作响应与误差累积。加速策略必须跑长时回归，而非只跑 77 帧。

建议的基准与验收口径

若只报 FPS，会掩盖首帧慢、VAE 阻塞、长时 KV 膨胀和多会话抖动。

证据、边界与可复核来源

结论以一手论文和官方仓库为主。仓库快速演进，因此将论文结论、当前代码事实与工程推断分开标注。

已确认事实

  • minWM 自称 framework/tutorial，而非特定 checkpoint。
  • 公开实例：Wan2.1-T2V-1.3B、HY1.5-TI2V-8B；480×832、77 帧、4 latent-frame chunk、4 steps。
  • 单 A800、排除 VAE：few-step AR 首帧为 1.137 s（Wan）与 3.446 s（HY）。
  • 代码已有 FSDP、SP、BF16、激活重算、FlashAttention，以及 HY AR rollout 的 text/vision KV。
  • Wan2.2 A14B 为 timestep 专家 MoE；27B 总参数、每步约 14B active。TI2V-5B 使用高压缩 VAE。

工程推断 / 尚需实测

  • 昇腾上 fused causal attention、图编译、量化和流水的具体收益尚无官方 minWM 数据。
  • rolling/paged KV、固定窗口、稀疏注意力属于生产化建议，不是论文默认配置。
  • 跨步 cache 在 4-step 上是否有净收益必须实测；不能直接套用 Wan2.2 多步结论。
  • 把 Wan2.2-A14B 作为 minWM 新底座需要重新训练/蒸馏和验证 timestep-MoE 路由，并非替换权重即可。
  • “实时”依赖分辨率、帧率、硬件和是否包含 VAE；本文不把论文的低首帧等同于端到端 24 FPS。
