01 / Executive summary

先减问题，再快算。

世界模型的成本由视频 token 数、上下文长度、去噪步数和模型宽度共同放大。LingBot 的路线清楚展示了优先级：把双向扩散适配为分块因果模型，用 KV Cache 消除历史重算，再将多步教师蒸馏成少步学生；最后通过混合并行、编译内核与异步流式系统补齐实时性。

COMPUTE SHAPE

降低计算阶数

因果分块把“整段视频反复全局注意”改成“只算新 chunk”；KV Cache 复用历史 K/V；局部窗口或动态缓存控制上下文增长。

MODEL STEPS

减少模型调用

一致性蒸馏、DMD 与对抗优化把数十步去噪压到少步。它通常比单纯换 attention kernel 更决定端到端速度。

PIPELINE

隐藏不可消除的延迟

生成、VAE 解码、增强、编码与传输并行；机器人分支再把动作执行与下一段预测重叠，改善首帧和闭环频率。

工程判断：“快”至少有三种口径：首帧延迟、稳定帧率和单位成本。LingBot‑World 2.0 的 720p/60fps 是论文中完整官方部署栈的结果；开源仓库只提供多 GPU 推理入口，且明确不发布部署代码，不能把论文数字直接当作开源脚本的复现承诺。
02 / LingBot family

三个分支，三个“快”的定义。

LingBot 不是单一模型。World 分支模拟可交互视频世界；VA 分支把世界预测用于机器人闭环控制；VLA 则是直接策略模型。优化时必须先区分目标，否则“画面帧率”和“控制频率”会被混为一谈。

WORLD · V1

LingBot‑World

基于 Wan2.2 的视频扩散世界模型，经历通用先验、中期世界知识/动作控制、因果适配与少步蒸馏三阶段。

  • Base：双向扩散，14B 推理模型；基础世界模型论文描述为双专家合计 28B
  • Fast：分块因果生成 + KV Cache
  • 训练：FSDP2 + Ulysses 上下文并行
  • 目标：16fps、亚秒响应、分钟级连贯性
WORLD · V2 / INFINITY

LingBot‑World 2.0

从“有限长后训练”进一步转向原生因果预训练，引入 MoBA mask、长自回滚 DMD 和动态 KV 管理。

  • 公开：14B causal-fast 权重与推理代码
  • 蒸馏：一致性蒸馏 + 长轨迹 DMD
  • 系统：异步 VAE、编译、混合并行、流式输出
  • 目标：官方栈 720p/60fps、无界交互
ROBOT · VA

LingBot‑VA

视频与动作 token 交错的自回归扩散世界模型，用视觉想象辅助逆动力学动作解码，强调低延迟闭环。

  • 架构：双流 MoT，共享跨模态注意
  • 降本：部分去噪，不追求像素完美
  • 缓存：视频—动作历史 KV Cache
  • 调度：预测与动作执行异步重叠，论文消融报告任务完成速度 2×
03 / Optimization stack

优化是链，不是点。

从输入数据到用户看到第一帧，每一层都会决定下一层的上限。最稳妥的顺序是先固定质量门槛与负载，再沿关键路径逐层消除冗余。

LATENCY PATH

交互优先

少步学生 → 小 chunk → 预填充/缓存 → 首帧增量解码 → 异步传输。允许后续增强或插帧在首帧之后完成。

THROUGHPUT PATH

离线吞吐优先

较大 bucket → 高设备占用 → 序列并行/批处理 → VAE 批量解码 → 更激进的编译与量化。未必获得最佳交互手感。

05 / LingBot deep dive

LingBot 的快路，分两代。

v1 的核心是把强大的双向视频教师“改造”为可缓存的因果学生；v2 则把因果性提前到预训练，并用 MoBA 保留双向生成先验，再在部署端补上动态记忆与完整流式系统。

V1 · ADAPT
从 Wan2.2 视频先验起步避免从零学习视觉真实性、物体恒存与基础动态。
中期训练世界知识与长序列双专家 MoE；动作通过 AdaLN 适配器注入，主干冻结以保护画质。
高噪声专家初始化因果学生论文认为其动态建模更强；用 block causal attention 支持 KV Cache。
DMD + 自回滚 + 对抗优化少步化同时在学生自己的长轨迹上训练；只对最近 K 步反传。
V2 · NATIVE CAUSAL
MoBA 因果预训练teacher-forcing mask 旁加入双向块，抑制只复制上下文导致的画质退化。
无泄漏 cross-attentionchunk prompt 按下三角因果访问；全局 prompt 供双向组件使用。
Consistency + long-rollout DMD前者压缩步数，后者让学生分布在长自回滚中贴近真实数据。
动态 KV + 异步全链路只保留当前控制最相关历史；生成、VAE、增强和传输重叠。
input image / current state / action / chunk prompt │ ├─ text & action encode ── exact cache ▼ causal few-step DiT ── KV reuse + efficient attention + hybrid parallel │ latent chunk │ next chunk starts ├───────────────────────────────────────┘ ▼ async VAE workers ── spatial upsample ── temporal interpolation │ (compiled engines / parallel workers) ▼ incremental encode & stream ── first visible frame ── continuous playback
不要误读 60fps：v2 论文明确包含空间增强与时间插帧 refiner。因此展示输出的 60fps 不等价于 DiT 原生生成 60 个独立物理状态/秒。评测交互世界时应分别报告“基础 latent 生成频率、解码帧率、插帧后显示帧率”。
06 / Training efficiency

长视频训练：显存只是第一关。

训练优化的目标不是单纯“塞进去”，而是让有效 token/秒随设备数增长，同时保证因果学生真正见过部署时的自身误差分布。

07 / Inference & serving

实时性是一条关键路径。

把一次交互拆为编码、预填充、少步 DiT、VAE、增强、编码与传输。先 profile 端到端，再决定下一项投资；只测单个 DiT kernel 会漏掉首帧排队和解码尾延迟。

ZERO / LOW LOSS

先做的四件事

  • 固定常用分辨率、chunk 长度和 CFG 路径，预热编译缓存
  • 使用 causal-fast 权重与 KV Cache，检查缓存命中/增长
  • 启用合适的 fused attention，消除隐式 CPU 同步
  • VAE 解码与下一 chunk 生成并行，首帧增量发送
QUALITY TRADE

再做的四件事

  • 降低 NFE / 使用更激进蒸馏学生
  • 缩小 native 分辨率后做超分与插帧
  • 权重 INT8/FP8/4-bit；敏感层保留 BF16
  • 稀疏或裁剪 KV；以事件/控制相关性保留记忆

量化的正确验收

对象建议必须观察
Text encoder可先权重量化或 CPU/offload；提示重复时做 embedding cacheprompt 跟随、首帧和 PCIe/NPU 传输
DiT Linear从 weight-only 开始；逐层敏感度扫描；确认低精度 kernel真实 latency 而非仅显存；长时漂移与动作误差
Attention / Norm保守保留 BF16，再评估 FP8；softmax/归一化通常更敏感NaN、颜色漂移、时序闪烁、极端 prompt

08 / Ascend transfer

迁移到昇腾：先保主路径。

开源 LingBot 实现以 CUDA、FlashAttention、torchrun/FSDP/Ulysses 为基线；v2 论文中的 TensorRT refiner 也属于 NVIDIA 部署栈。因此昇腾迁移应把“论文机制可迁移”和“现成代码可运行”分开评估。

模块迁移判断优先动作主要风险
Causal DiT最高价值；标准算子为主先 BF16 eager 对齐 → 固定 bucket 编译 → attention 融合RoPE/QKV layout、动态 mask、graph break
KV Cache机制完全可迁移预分配连续缓存；chunk/会话级生命周期；动态裁剪显存碎片、频繁 concat、cache layout 转换
FlashAttentionCUDA 实现不可直接用映射 NPU fused attention/torch_npu SDPA；核对 mask 支持MoBA/block-causal mask 可能触发 fallback
Ulysses / 混合并行框架可迁，通信需重调按 HCCS/集群拓扑放置 CP；测 all-to-all小 chunk 下通信反噬；多维并行组合复杂
VAE / Refiner需替换 TensorRT engine独立进程/设备先跑通；再编译或自定义算子上采样、3D conv、视频插帧后端覆盖
4-bit / FP8以实际 kernel 为准先 W8A8/FP8 可用路径，再做权重 4-bit 原型只省显存不加速；反量化拖慢主循环
昇腾 P0：把 14B causal-fast 的单 chunk BF16 数值跑通，打通 block-causal mask 与 KV Cache，再测 attention、MLP、VAE 三段火焰图。不要先移植 Agentic Harness 或时空 refiner，它们不在最小生成闭环上。
09 / Delivery roadmap

四阶段落地。

基线：建立可复现的端到端账本

锁定模型 revision、权重、分辨率、帧数、chunk、NFE、seed 与硬件；同时记录冷/热启动、TTFF、稳定 fps、峰值内存和各阶段耗时。

GATE · 分段耗时合计与端到端误差 < 5%；固定输入结果可复现
官方快路：因果学生 + KV + 异步 VAE

优先使用 causal-fast；核实 KV 真正复用；固定 shape bucket；把 VAE 放到下一 chunk 的并行支路；增量输出首帧。

GATE · 画质/动作门槛通过；TTFF 与稳定吞吐均形成明确收益
运行时：融合、编译、混合精度与并行

attention backend A/B；编译重复 DiT block；按拓扑选择 CP/TP；对 Linear 做逐层量化敏感度扫描。

GATE · 无频繁重编译/fallback；低精度端到端确有实速而非仅省显存
高级策略：动态记忆与质量恢复

根据控制/场景相关性选择 KV；加入周期性关键帧刷新；低 native 分辨率配套轻量超分/插帧；建立失败自动回退。

GATE · 进入质量—延迟 Pareto 前沿；60 分钟压力测试无灾难性漂移
10 / Measurement contract

不要只报 fps。

世界模型优化最容易“偷换口径”。一份可信报告必须同时给出计算效率、交互响应、视觉质量、动力学/控制正确性和长时稳定性。

维度指标注意事项
延迟TTFF、每 chunk P50/P95、控制到可见响应、cold/warm包含排队、文本编码、VAE、编码和网络
吞吐native latent fps、decoded fps、refined/display fps、samples/h三种 fps 分开，注明设备数和并行方式
资源峰值/常驻显存、KV 增长率、功耗、GPU/NPU·s/分钟视频长会话不能只测前 10 秒
视觉短片质量 + 身份/布局/风格保持；闪烁、边界与插帧伪影自动指标配人工盲评；固定与随机 seed 都测
动力学/控制动作响应延迟、轨迹误差、因果一致、事件完成率画质好不代表控制正确
长时稳定1/5/20/60 分钟漂移、崩溃率、KV 淘汰前后突变专门覆盖回访场景与远距离返回
