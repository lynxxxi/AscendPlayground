01 · Scope & taxonomy

先把“变分”说清楚

本文主线：生成式迭代模型

这里把“变分模型”按工程语境扩展为扩散、流匹配及其视频 / 动作生成变体。它们共享“多步去噪或流积分 + Transformer 主干 + VAE / 感知编码器”的主要成本结构。

不混为一谈

LingBot-Depth、Map、Vision 属于重要感知与几何模块，但不直接套用“减采样步数”逻辑；它们适用的是编码器编译、分辨率分桶、蒸馏和算子融合。

02 · Cost anatomy

优化对象不是一个模型

端到端延迟由条件编码、多步主干、可选专家通信、VAE、后处理与调度共同构成。视频长度和空间分辨率同时放大 token 数；全注意力的时间与显存又对 token 数近似呈二次增长。

Te2e = Tencode + Nsteps × [Tattn(S) + TMLP/MoE + Tcomm] + TVAE + Tpost + Tqueue
MULTIPLIER

采样步数 N

每少一步就少一次主干前向，通常是最直接的一阶收益。可用一致性 / flow / progressive distillation、改进求解器或任务允许的动态早停。

TOKEN SCALE

序列长度 S

压缩 VAE、时空 patch、帧率、分辨率、局部 / 稀疏注意力与 context parallel 都围绕 S。长视频应优先改复杂度，而不只是换更快 GEMM。

BOTTLENECK

非主干成本

VAE 解码、Depth / DINO teacher、渲染与传输可能在主干加速后接管火焰图；必须持续重做端到端 profiling。

判断顺序：若目标是最低单请求延迟，先看步数、因果缓存和编译；若目标是最大吞吐，先看 batch / bucket、并行拓扑、专家路由与服务调度；若目标是单卡可运行，先看模型选择、FSDP / offload、顺序 CFG、VAE tiling 与量化。

05 · Training stack

训练：把 GPU 等待变成有效样本

DATA

先离线化昂贵 teacher

  • 缓存 text / depth / DINO teacher 特征
  • 统一短边、帧数、动作长度 bucket
  • 异步 decode、pin memory、预取与持久 worker
  • 先过滤失配 / 模糊 / 静止数据再进训练
PARALLEL

分片策略按瓶颈组合

  • FSDP2 分参数 / 梯度 / 优化器状态
  • CP 沿时空 token 切长序列
  • MoE EP 沿专家切分并优化 all-to-all
  • 梯度累积只解决显存，不等于吞吐提升
NUMERICS

低精度分区而非一刀切

  • BF16 作为稳定基线
  • GEMM / expert 尝试 FP8
  • norm、softmax、loss、VAE 敏感区保高精度
  • 记录 overflow、amax、grad norm 与 loss parity
MEMORY

选择性激活重计算

只 checkpoint 显存占用高、重算性价比好的 Transformer block；避免对 teacher、VAE 或小算子全量重算。activation offload 只有传输能被计算隐藏时才成立。

COMMUNICATION

拓扑决定理论值能否兑现

把 CP / TP / EP 优先放在高速互联域内，DP 跨域；用分层 all-reduce、梯度 bucket、通信计算重叠，并单独报告网络等待占比与专家负载偏斜。

训练优化的最小实验顺序
00 freeze data + seed + checkpoint revision 01 BF16 baseline → samples/s, MFU, peak memory, loss curve 02 fused attention / FlexAttention [numerical parity first] 03 FSDP2 → add CP only when sequence length requires it 04 input buckets + offline teacher cache + prefetch 05 selective activation checkpoint + compile repeated blocks 06 FP8 GEMM / expert [keep sensitive ops in BF16/FP32] 07 scale 8 → 16 → 32… devices and report efficiency, not only throughput
06 · Inference stack

推理：六层漏斗

L0 / REQUEST

路由

按延迟、质量和显存预算选择 Dense / MoE、base / fast、是否 Refiner、分辨率与帧数。模型路由往往比内核微调收益更大。

L1 / ALGORITHM

减步与缓存

少步蒸馏、动态步数、因果 KV cache、条件复用。优先消灭整次前向，再谈单次前向更快。

L2 / GRAPH

编译与分桶

固定帧数 / 分辨率 / batch bucket，编译 repeated blocks；监控 guards、recompile 与 graph break。

L3 / KERNEL

融合算子

fused attention、RMSNorm、RoPE、grouped GEMM、fused MoE。以内存带宽与 kernel launch 火焰图决定投入。

L4 / MEMORY

精度与驻留

BF16 → FP8 / INT8；base 与 refiner 分阶段驻留；VAE tiling；必要时 text encoder CPU offload。

L5 / SERVICE

调度

预热、编译缓存、continuous batching、同 bucket 合批、背压、超时降级和模型池。分开报告排队与执行延迟。

三条禁区：不要把“显存下降”写成“延迟下降”；不要把多卡聚合吞吐写成单卡吞吐；不要以 CLIP / FID 一项替代长视频一致性、几何稳定性和机器人闭环成功率。
07 · Ascend translation

昇腾：迁移机制，不照搬开关

LingBot 官方仓库主要给出 CUDA 路径。迁移到昇腾时，先保留算法结构与张量语义，再替换后端：FlashAttention 对应 NPU 融合注意力，CUDA Graph / compile 对应稳定 shape 的图执行，FSDP / CP 对应分片并行；SGLang fused MoE、FP8 expert 与自定义 CUDA 扩展不能假设直接可用。

CUDA / 官方路径昇腾落点首要检查策略
flash-attn / SDPAtorch_npu 融合注意力或原生 SDPA 后端mask、causal、head dim、layout、精度先等价，再融合
torch.compileNPU 编译后端 + 静态 bucketgraph break、重编译、动态帧长只编稳定子图
CP8 / Ulysses沿时空 token 的 context parallelall-to-all 占比与 HCCS / 网络拓扑由长序列触发
grouped_mm / fused MoEGrouped MatMul / 自定义 MoE kernel路由排序、padding、专家负载与通信Video / VLA 专项
FP8 / NF4目标 NPU 原生低精度格式与量化工具链是否真有计算 kernel，Q/DQ 是否抵消收益不得仅转换权重
VAE tiling框架无关的 tile / overlap 解码tile seam、峰值显存与额外耗时可优先迁移
边界：本节是机制级迁移建议，不宣称 LingBot 官方已验证昇腾支持。具体 API、精度格式与算子覆盖随 CANN / torch_npu 版本变化，落地时需锁定版本矩阵并以目标设备实测。
08 · Delivery roadmap

四阶段落地与验收

Phase 0｜一周：冻结基线

锁定 checkpoint、prompt / 视频 / 任务集、随机种子、分辨率、步数、硬件与软件版本；分段埋点 encode / DiT / VAE / refiner / queue。

GATE：分段耗时合计与 e2e 误差 < 3%
Phase 1｜一至两周：官方快路

启用官方 fast / compile / KV cache / FSDP / CP / sequential CFG / VAE tiling；先建立每条路径的 Pareto 基线。

GATE：质量门禁全通过且 P50 / P95 可复现
Phase 2｜二至四周：图、算子与低精度

静态 bucket、融合注意力、grouped expert、FP8 / INT8 分区量化、条件缓存；逐项 A/B，不叠开关猜收益。

GATE：速度收益扣除预热 / 编译成本后仍成立
Phase 3｜持续：服务与硬件专项

continuous batching、模型池、缓存淘汰、NPU 自定义热点算子；对漂移样本自动回退到保守路径。

GATE：线上 SLO、成本与质量报警闭环
