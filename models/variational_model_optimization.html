01 · Deployment scope

这里的“推理”就是模型前向

报告只覆盖已经训练好的摊销推断器：给定新输入 x，encoder 一次前向输出后验 qφ(z|x) 的参数，再返回均值、方差、样本或下游预测。经典 CAVI/SVI 的逐样本优化，以及任何参数更新，都不纳入部署主线。

x → preprocess → encoderφ(x) → posterior parameters → sample / statistics → downstream output
Latency一次前向多快拆分预处理、encoder、采样和后处理的冷/热 P50/P95。
Throughput单位时间处理多少批处理、shape bucket、编译与异步流水决定 QPS。
Memory单请求占多少权重、激活、后验参数与样本数量共同决定峰值显存。
Quality分布是否可用校准、覆盖率、下游精度与样本稳定性约束加速幅度。
02 · Forward architecture

部署关键路径是 encoder，不是训练闭环

摊销变分推理把“求后验”固化进 inference network。上线后 φ 已冻结：encoder 从观测直接预测均值、尺度或更复杂的分布参数；如果下游只需要分类、风险或不确定性，decoder 根本不在关键路径上。

POINT PREDICTOR

普通前馈推理

  • 一次前向输出单点标签、分数或 embedding。
  • 后处理通常确定，不需要随机采样。
  • 质量主要看任务精度和吞吐。
AMORTIZED POSTERIOR

一次前向输出分布

  • encoder 输出 μ、σ、logits 或结构化后验参数。
  • 下游可直接使用统计量，也可按预算生成 K 个样本。
  • 除任务精度外，还必须检查校准、覆盖率与随机稳定性。
01 / INPUT输入 x图像、序列、表格或传感器观测。
02 / PREPROCESS固定预处理归一化、tokenize、resize；与训练配置严格一致。
03 / ENCODE推断网络 qφ冻结权重做一次前向，输出后验参数。
04 / PARAMETERIZE构造分布对角高斯、低秩、categorical 或 flow 参数。
05 / READOUT统计量或 K 个样本按任务选择均值、方差、分位数或随机样本。
06 / OUTPUT下游结果预测、风险、不确定性或可选 decoder 输出。
FAST PATH

直接返回统计量

分类、风险排序和不确定性展示优先使用 μ、σ 或概率向量，完全跳过随机采样。

SAMPLE PATH

确实需要时才采样

生成、Monte Carlo 决策或置信区间才启用 K 个样本，并把 K 作为服务预算。

OPTIONAL DECODER

decoder 不一定在线

只有重建、生成或 likelihood 任务需要 decoder；不要默认把整套 VAE 都放进推理关键路径。

报告边界：无 ELBO 更新、无 backward、无 optimizer、无梯度同步。若业务需要测试时训练或逐样本优化，应另立报告与服务队列，不能混进常规推理延迟。
03 · Latency anatomy

一次部署前向花在哪里

01 / INPUT预处理与搬运decode、resize、tokenize、CPU→device。
02 / ENCODER推断网络前向通常是主要 GEMM / attention 成本。
03 / POSTERIOR参数变换softplus、归一化、flow 与协方差构造。
04 / READOUT统计量 / K 样本K 增大时随机数、广播和下游计算增长。
05 / OUTPUT后处理与返回decoder、聚合、序列化或跨服务传输。
Trequest = Tpreprocess + Tencoder-forward + Tposterior + K × Treadout + Tpostprocess
最常见误判：把训练 profile 当推理 profile，或默认 K 越大越好。部署先尝试 K=0 的统计量快路和 K=1 基线，再按实际下游质量决定是否增加样本。

05 · Sampling and readout

采样不是默认步骤

STATISTICS

均值 / 方差快路

若下游只消费风险、置信度或 embedding，直接返回后验统计量；这是最低延迟、最易批处理的路径。

K SAMPLES

按业务预算采样

生成、置信区间或 Monte Carlo 决策才需要样本。K 从 1 开始，向量化执行，并用质量曲线决定上限。

DETERMINISM

随机状态可复现

请求显式携带 seed / RNG 状态；批大小变化、并发和设备切换后仍要满足定义好的数值容差。

部署采样基准
固定 model revision、input、dtype 与 seed 比较：statistics only / K=1 / K=4 / K=16 记录：P50/P95 latency、QPS、峰值显存、输出校准、下游质量 检查：vectorized on/off、batch size、compile、设备切换 最终选择：满足质量门的最小 K，而不是样本最多的配置
06 · Serving paths

四条部署路径怎么选

FAST / STATISTICS

默认路径：一次前向

预处理 → encoder → μ/σ/probability → 返回。适合高 QPS 预测、排序和实时不确定性服务。

SAMPLED

需要随机输出：K 样本

同一后验参数下向量化生成 K 个样本；不要重复运行 encoder。按延迟预算限制 K，并对结果聚合。

SEQUENTIAL

时序输入：缓存状态

过滤式 encoder 复用上一时刻 hidden state、充分统计量或固定条件特征；检测分布突变后清空缓存。

FALLBACK

困难样本：切高质量模型

低置信度请求路由到更大的冻结 encoder、更高精度或更多样本，而不是在在线路径里启动反向传播。

关键边界：难样本升级的是冻结推理配置，不是 optimizer。任何 test-time optimization 都应进入独立的慢队列，并从本报告的常规推理 SLO 中剥离。
07 · Inference runtime

让每次后验求解更便宜

VECTORIZE

批量化样本轴

batch、序列与 K 样本都成为张量维度。优先消除 Python for-loop，再做算子融合。

COMPILE

固定结构与 bucket

按 batch/序列长度分桶，编译稳定的 encoder-forward 图；动态路由留在图外。

PRECISION

分区低精度

encoder GEMM 用 BF16/FP8；scale、softplus、方差、logsumexp 等敏感归约保 FP32，并做校准回归。

在线服务：按成本路由

默认统计量快路；只有任务明确需要时才采样。按输入 shape、后验族与 K 分桶，分别报告 encoder、采样和后处理延迟。

缓存与预计算

静态特征、索引、mask 与条件 embedding 可缓存；流式场景复用 encoder state。缓存键包含模型 revision、预处理版本和 dtype。

推理服务的延迟预算模板
T_total = T_preprocess + T_encoder_forward + T_posterior + K × T_sample + T_post P50 路径：encoder → statistics → return P95 路径：larger frozen model / higher precision → optional K samples → return 优化顺序：裁剪无用分支 → batch/bucket → compile → quantize → 向量化 K
08 · Decision route

按症状选第一步

01

encoder 占绝大多数延迟

profile 热点 → 固定 shape bucket → compile → BF16/FP8/INT8 → 检查 kernel 是否真实生效。

02

采样导致延迟线性增长

确认下游是否真的需要样本 → 统计量直出 → K 从 1 起做质量曲线 → 多样本向量化。

03

显存不足或 batch 上不去

decoder bypass → 权重量化 → activation 生命周期检查 → 预分配输出 → 再考虑模型切分。

04

GPU 利用率低

合并小请求 → 输入 shape 分桶 → CPU 预处理并行 → H2D 与 encoder 前向异步流水。

05

线上尾延迟超 SLO

限制合批等待 → 快慢路径分队列 → 设置 K / dtype 降级 → 冷启动预热 → 超时返回保守统计量。

09 · Validation

四道验收门

门槛必须报告常见失败
数值一致后验参数误差、固定 seed 样本差、dtype/compile parity量化后 scale 下溢、随机状态不可复现
后验质量校准、覆盖率、下游精度、K—质量曲线只看均值误差，不看不确定性
推理效率冷/热 P50/P95、QPS、K、峰值显存、超时率隐藏编译、排队、预处理和 decoder 成本
推荐基准命名：model@revision / posterior-family / output-mode(statistics|K) / batch / dtype / device×count / compile / seed×N / quality-gate。所有“×倍加速”只与同输入、同输出语义和同质量门的基线比较。
