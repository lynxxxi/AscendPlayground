01Ring 的收益前提与三条硬约束

所有后文的适配性分析都建立在同一个机制事实上，所以必须先把它写清楚。 Ring Attention 的代价模型是：用 P 倍的 KV 通信，换 1/P 的 KV 显存。

# 每 rank 每层（b：元素字节，S：序列长，N_kv：KV 头，D：头维，P：并行度）
M_ring = KV_total / P ← 显存收益，随 P 线性下降
Comm = KV_total · 2(P−1)/P ← 通信代价，约 2× 一次性拉取

# 原论文的显存模型（arXiv 2310.01889）
M_ring = b · 6 · c · h ← 随块大小 c 线性，与序列长度无关
1 块 query + 2 块当前 K/V + 2 块接收中 K/V + 1 块输出

# 通信被计算掩盖的条件 —— 这是 Ring 的收益前提
4·d·c² / F ≥ 4·c·d / B ⟹ c ≥ F / B

机制本质：Ring 是一个深度为 P 的流水线

Ring 不是「把序列切开各算各的」，而是每个 rank 持有本地 Q，K/V 块沿环流转 P 次， 每轮做一次 blockwise attention 并用 online softmax 累加。收益来自 第 i 轮的通信与第 i+1 轮的计算重叠。 如果重叠成立，通信就是免费的；如果重叠不成立，Ring 会退化成一个纯通信开销极大的方案。

2025-11-28 的 db-SP 实测之所以对你的课题重要，是因为它是目前唯一把「Ring + 块稀疏」的 负载不均衡量化出来的工作：Ring 的 ρ_s 在 1.255–1.269，明显低于 Ulysses 的 1.355–1.447。 Ring 沿序列/块切分，把头间的稀疏度差异摊薄了。

1.1 三条硬约束（后文所有判定都从这里推出）

#约束来源对稀疏/量化的含义
C1 每轮一个同步点，且预算固定 Ring 的流水线结构：每步 P2P 都要等对端 任何 rank 间计算量差异都会直接暴露成等待。
稀疏必须保证每个同步周期内各 rank 的块数相等，而不只是总量相等
C2 不引入额外全局屏障 Ring 的价值在于「没有全局同步」；任何量化前的前置 all-reduce都会独占一段无法与 attention 重叠的时间 禁止 per-tensor amax 型量化；禁止需要全序列统计量的稀疏打分
C3 块是最小传输单元 环上流转的是 K/V 块，块大小 c 决定通信粒度 量化 scale 必须挂在块上一起走；稀疏决策也必须以块为粒度

一个必须先说清的好消息

对视频 DiT（full attention，非因果）而言， Ring 最麻烦的结构性问题不存在：因果三角导致的 1:2:…:P 负载不均衡、 zigzag / Striped 配对、以及每轮掩码形态不同的问题，在非因果场景下都不需要处理。

这意味着 DiT 上的 ring 每轮所有 rank 都是稠密满算——前提是不加稀疏。 一旦引入块稀疏，C1 立刻被激活。这正是第 3、4 节要处理的核心矛盾。

例外：自回归视频生成（如 Magi-1，约 400 万 token）的掩码是 varlen block-causal， 因果问题会回来，且 Ring 的 P2P 冗余会从 25% 升到 >33%（MagiAttention 定量）。

02稀疏 × Ring：可行性判定

2.1 一个关键的几何事实

先建立一个容易被忽略的事实：因果块稀疏掩码，永远是因果稠密掩码的子集。

也就是说，一个 query 块需要的所有 K/V 块，因果 ring 本来就都会送到它手上。 Ring 并没有「送错块」的问题——它的问题是把所有块都算了。

推论：Ring + 块稀疏的改造目标不是「怎么把需要的块送到」， 而是「送到之后怎么决定算哪几个」。这个视角转换会让后面的分析清晰很多。

2.2 判定维度：稀疏决策依赖什么

把稀疏方法按「决策依据」分类，就能得到一个干净的可行性判定表。 核心问题只有一个：决定「算哪些块」所需的信息，在 ring 的单步局部视野里拿得到吗？

稀疏掩码是否只是「块位置坐标」的函数？

是 → 可以在 Ring 上工作。掩码可离线确定，每个 rank 收到块时立刻知道算不算。

否（依赖 Q/K 的数值、需要跨块聚合、需要全局排序）→ 在朴素 Ring 上不成立， 需要第 5 节的两条改造路线之一。

03为什么 Top-k 在 Ring 上不成立

这是你问的核心问题。下面把它拆成四个独立的障碍，每一个单独都足以致命。

障碍一：循环依赖 —— 要算分数，必须先有 K

Top-k 的决策依据是重要性分数 s(q_i, k_j)，最常用的是 s_ij = q_i · k_j^T（或用池化后的 Q/K 近似）。

在 Ring 上，第 j 个 K 块要到第 j 轮才到达。 所以要得到完整的分数向量，必须先跑完整个环。

# 循环依赖
要选 Top-k 块 → 需要全序列分数 → 需要全部 K 块 → 需要跑完环
但跑完环就等于把 attention 算完了 → 稀疏失去了意义

这与 dense ring 有本质区别：dense ring 每轮收到块就立刻消费它， 通信被计算掩盖。而 Top-k 每轮只能攒着，攒完才能决策—— 流水线从「流式消费」退化成「先收集后处理」，通信完全暴露在关键路径上。

障碍二：Top-k 集合与 Q 属主耦合 —— 跨 rank 无法预判

这是比障碍一更微妙、也更难绕过的一点。

阶段Q 的分布问题
Ring（attention 期间） 每个 rank 持有一段 Q 块（S/P） 不同 Q 块的 Top-k 集合完全不同。

而 K 块的「该不该传」是全局决策：
一个 K 块可能被 rank 2 的 Q 需要、被 rank 5 的 Q 忽略。

Ring 的 K/V 是广播式流动（每个 rank 都会经手所有块），
所以只要任一 rank 需要，这个块就得传——
传输跳过只能做「全局都需要的块」的并集，收益被大幅压缩。
Ulysses（attention 期间） 每个 rank 持有完整序列的 Q

这解释了为什么 FVAttn 的方案能成立、而它不能直接搬到 Ring

FVAttn 明确写了它的前提是 Ulysses 风格： 「each GPU holds complete sequences for a subset of attention heads」。

在这个前提下，每个 rank 的 Q 是完整的，所以它可以： ① 在掩码 materialize 后看到自己负责的 head 的真实负载； ② 用「迁移 head」而不是「迁移块」来做均衡—— 因为 head 是完整可搬运的单元。

而在 Ring 上，每个 rank 只有一段 Q，没有「完整的 head」可以搬运。 FVAttn 的调度单元在 Ring 上不存在。这是它不能直接迁移的根本原因，而不是实现细节问题。

障碍三：预取失效 —— P2P 前向的代价

Ring 的块是链式流转的：rank i 发给 rank i+1， 每一跳都要经过中间节点。这与 AllGather 的树形或环形集合通信不同。

# 要让 rank g 提前拿到「属于它未来要用的 Top-k 块」
# 该块必须从属主 rank 出发，沿环前进多跳：
cost = d × block_size × hops ← d 为环上距离

# 而正常 ring 每轮只前进 1 跳。跳数越多：
① 延迟越大（无法与近端计算重叠）
② 中间 rank 的转发带宽被占用
③ 破坏 double buffer 的固定节奏

障碍四：不规则工作集破坏流水线节奏

这是 C1 的直接后果，也是最容易被低估的。

Ring 的收益完全建立在「每轮延迟相近、通信能被下一轮计算掩盖」之上。 Top-k 的选择结果天然不规则：

  • 不同 Q 块选中的块数相同（都是 k），但它们落在不同的环上位置；
  • 于是每一轮各 rank 的实际计算量不同——有的 rank 这一轮要算 5 个块， 有的一个都不用算；
  • 每轮都有同步点，所以每轮的最慢 rank 决定这一轮的延迟， 而最慢的 rank 每轮都在换；
  • 结果是：每轮的通信都无法被掩盖——因为「是否有足够计算可掩盖」 本身就不确定了。

这正是 db-SP 量化的那个 ρ_s 的来源，只不过它测的是 Ulysses 与 Ring 的整体不均衡； 在 Top-k 场景下，Ring 的逐轮不均衡比整体不均衡更严重， 因为 Ulysses 只有一个同步点（attention 之后），而 Ring 有 P 个。

3.4 小结：Top-k 在 Ring 上的四个障碍

#障碍本质能否工程绕过
1循环依赖：选块需要全部 K，拿到全部 K 就等于算完了信息时序部分：用低分辨率代理（见 5.2）
2Top-k 集合与 Q 属主耦合，Ring 下无「完整 head」可搬运数据布局难：需要按 Q 属主分区，与 ring 广播流冲突
3预取需沿环前进多跳，代价 ∝ 距离P2P 拓扑部分：把预取合并进正常轮次
4逐轮负载不均，破坏通信/计算重叠流水线部分：需要逐轮调度，不是整体均衡

正因为如此，两条现实路线是：要么把稀疏改成「可离线确定」的（第 4、5.1 节）， 要么用低分辨率代理把决策提前（第 5.2 节）。

04OSP-Next 为什么只需一次 All-to-All

Yunyang Ge 等（北京大学 PKU-YuanGroup / 南洋理工 / Rabbitpre AI）· arXiv:2605.28691 · 2026-05-27 · abs · HTML（含 Algorithm 1 伪码）

4.1 先把「为什么 Ulysses 要 4 次」说清楚

你的困惑很可能是从这个对比产生的。Ulysses 的 4 次 All-to-All 来自： Q、K、V 各自要换一次（3 次），输出再换回来一次（1 次）。 原因是 Ulysses 换的是「序列维 ↔ head 维」： 它把「每卡一段序列」变成「每卡一部分 head 的完整序列」， 而 Q、K、V 是三份独立张量，各换各的。

4.2 Skiparse Rearrange 的「局部等价性」是什么

看论文 Algorithm 1 的伪码最清楚。orig_to_tsa 这一行是全部关键：

def orig_to_tsa(x, T, H, W, P):
    return rearrange(x, "b (t h p w q) c -> (p q b) (t h w) c",
                      p=P, q=P, h=H//P, w=W//P)

它做的是像素 unshuffle：把一个 H×W 的图， 按 (p, q) 下标拆成 P² 个子图，每个子图 (H/P)×(W/P)。

关键性质：这个 rearrange 是「单元局部」的

对整张 H×W 图做 rearrange，等价于独立地对每个 k²×k² 的最小单元做 rearrange。

为什么这重要？因为它直接把「全局重排」降级成了「局部重排」：

  • 一个 token 该进哪个真子序列，只由它自己的 (h, w) 坐标决定， 不需要知道其他 token 在哪里；
  • 因此这个映射可以离线预先算好（一个固定的索引表）， 运行时不需要任何跨 rank 协商；
  • 更关键：这个 rearrange 与序列切分是可交换的—— 先切分再各自 rearrange，和先 rearrange 再切分，结果一致。 这正是「可以分配给不同 rank 各自算」的合法性来源。

4.3 一次 All-to-All 到底在搬什么

看 sparse_sequence_parallel 的四步。有一个容易被忽略的细节： 它在函数内部一次性做完了 TSA 变换，然后才进入交换。

G = P² / group_size          # 真子序列被分成 G 组
b = B_local / G              # 每组对应 b 个原 batch 元素

# ① 本地 rearrange（无通信）：把序列拆成 P² 条真子序列，拼到 batch 维
x = orig_to_tsa(x, T, H/P, W/P, P)      # → [(p q b), (t h w), c]

# ② 一次性 All-to-All：一次性完成「序列维切分 → 真子序列维切分」的换轴
x = x.view(group_size, G, G*b, base, C)
all_to_all_single(recv, x, group=group)

# ③ 本地置换 + ④ 反向 rearrange（无通信）

# 论文自己的总结（原文）：
#   "data exchange to be completed by ONE local rearrangement on each rank
#    followed by ONE All-to-All communication step within the communication group"
所以「为什么只要一次」

1. 换的是「轴」，不是「张量」。 这里只有一份激活 x（Attention 的输入）， Q/K/V 在后面用权重投影出来——所以不需要像 Ulysses 那样分三次搬 Q、K、V， 也不需要第四次搬回输出。这是「1 次 vs 4 次」最主要的原因。

2. 目的地可离线确定，所以不需要单独的「全局求解」阶段。 这是更深层的原因。一般的动态稀疏方案需要两阶段： ① 全局求解「哪个 token 该给哪个 rank」（这一步要看到全局信息， 在 Ring 上代价高昂甚至不可能）；② 一次 All-to-All 去实现它。 局部等价性把 ① 消除了——索引表是固定的，直接执行 ②。

3. 真子序列等长 → 交换天然均衡。 因为每个 rank 收发等量数据，All-to-All 是一对一的规则交换，不需要额外均衡； 切分后各 rank 计算量天然相同（不触发 C1）。

4.4 但要注意：这个机制解决的是「模式切换」，不是「稀疏选择」

这一步很关键，避免把 OSP-Next 的能力理解过头：

  • 那一次 All-to-All 的作用是在 token-wise（TSA）与 group-wise（GSA）两种模式之间切换， 因为两种模式的真子序列划分不同，token 需要换手。
  • 它不是「把需要的 KV 块拉过来」——Skiparse-2D 根本不需要拉， 因为它的稀疏性来自「每条真子序列内部做稠密注意力」， 而不是从全序列里挑块。
  • 换句话说：OSP-Next 的「稀疏」是把序列重组成多条短序列，然后各算 dense。

这正是它绕开第 3 节全部四个障碍的原因： 不需要打分、不需要全局排序、不需要预取、子序列等长所以负载天然均衡。 它把「稀疏选择问题」转化成了「固定重排问题」。

4.5 对你项目的直接含义：把它放到 Ring 上

Skiparse-2D 是 Ring 最友好的稀疏形态

OPS-Next 自己也选了 All-to-All（SSP），但那一次 All-to-All 是为了模式切换。

关键问题是：如果改到 Ring 上，还需要这次 All-to-All 吗？

分析：Skiparse-2D 的掩码完全由 (t, h, w) 坐标决定， 而 Ring 下每个 rank 持有的 Q 块对应一段连续序列—— 这段序列的 (h, w) 范围是本地已知的。 因此：

  • 稀疏决策不需要任何跨 rank 信息——每个 rank 独立判断自己的 Q 该和哪些 K 位置交互；
  • K/V 块沿环流转时，每个 rank 用本地已知的掩码规则决定「这个块与我本地 Q 的关系」， 不需要重排；
  • 所以 可以完全不做 All-to-All，直接以「环 + 固定掩码」实现—— 模式切换的代价从「一次 All-to-All」变成「一次掩码规则切换」（零通信）。

这是一个明确的研究空白，也是我认为你项目里最值得做的方向： OSP-Next 证明了「规则化稀疏 + 序列并行 + 8bit 量化」在视频生成上可行 （VBench 83.73% 超过 Wan2.1 基线，950PR 单卡 2.27×）， 但它用的是 All-to-All；把同一套稀疏形态搬到 Ring 上， 理论上可以同时拿到「显存 1/P」和「零稀疏通信」。

前提条件：k² 必须整除序列切分粒度，且 Ring 块大小应是 k² 的整数倍，否则 Q 块与最小单元不对齐，掩码规则要处理边界。 这一点需要实测确认。

05适配 Ring 的两条工程路线

5.1 路线 A（首选）：把稀疏改成「可离线确定」

做法：约束稀疏掩码只是「块位置坐标」的函数，不含任何数据依赖项。

可用的形态：

  • Skiparse 类：固定 skip 间隔 + 交替模式（OSP-Next，见 4.5）；
  • 滑窗 + 全局块：每个 Q 块看本地窗口 + 少量固定全局块；
  • 块因果 + 条带：适用于自回归视频；
  • 静态掩码 + 块内自洽：如 PAROAttention 的抽象静态掩码思路。

收益：直接绕开第 3 节全部四个障碍；不需要新算法；与 Ring 的流水线天然兼容。

代价：稀疏的「智能程度」下降。但 OSP-Next 的实测说明这个代价在视频上 比想象中小——固定规则模式拿到了超过 full-attention 基线的 VBench。 原因是视频的注意力冗余沿空间/时间邻域聚集， 规则化掩码足以覆盖大部分重要交互。

5.2 路线 B（备选）：用低分辨率代理提前决策

思路：不要在原始分辨率上打分，而是在下采样后的 KV 上跑选择器。 这直接缓解障碍一（循环依赖）——因为代理 KV 很小，可以在 ring 开始前就准备好。

# MInference 的思路可迁移：垂直-斜线模式 + 块稀疏，
# 离线为每个 head 定 pattern，在线只建 index

# 代价：代理的字节量约为 KV 的 1/r
proxy = KV_total / r ← r 为下采样比（如 32）
该代理仍需用 all-gather 拉齐或随环流转一次

风险：

  • 代理的统计量虽然小，但仍然需要一次全局可见性， 这会引入一个新的同步点（触碰 C2）；
  • 代理给出的块级决策是近似的，误差会直接进入注意力输出；
  • 代理决策仍然逐 Q 块不同，障碍二（Top-k 集合与 Q 属主耦合）没有解决—— 只是把「需要全精度 K」换成了「需要低精度全局 K」。

结论：路线 B 能缓解障碍一和三，但解决不了障碍二和四。 只有在路线 A 的规则形态不足以达到质量目标时才考虑。

5.3 两条路线的取舍

路线 A：可离线确定的稀疏路线 B：低分辨率代理
绕开障碍一（循环依赖）是部分（代理可提前准备）
绕开障碍二（与 Q 属主耦合）是否
绕开障碍三（预取多跳）是（无需预取）部分
绕开障碍四（逐轮不均）是（结构上均衡）否（仍需逐轮调度）
新增全局同步点无有（代理聚合）
稀疏质量上限中（规则化）较高（数据自适应）
公开证据OSP-Next（但用 All-to-All）仅单卡（MInference 等）

06量化 × Ring：scale 作用域分析

量化的适配性问题可以收敛成一个问题： scale 的作用域，与 ring 上块的边界，对不对齐？

6.1 四种 scale 粒度在 Ring 上的表现

scale 粒度Ring 适配根本原因典型来源
per-tensor
（全局 amax）		 ❌ 破坏 Ring 前提 需要一个前置 all-reduce。这个同步点在任何块进入环之前就必须完成， 因此它独占一段无法与 attention 重叠的时间——直接违反 C2。 相当于把 Ring 退化成一个带全局屏障的算法。 标准 FP8 E4M3 训练
per-token
（逐 token/行）		 ⚠ 技术上可行，系统上不利 scale 与 token 绑定，token 在哪个块里是可追踪的，所以语义上能随块流转。 但论文明确批评：需要先算 token-wise 最大值，引入 reduction 开销并造成 MatMul 前的串行依赖——“部分抵消了 8bit 计算的效率收益”。 细粒度 FP8 训练
per-tile / per-block
（如 128 token、128×128）		 ✅ 与 Ring 天然对齐 scale 与块边界严格绑定，块内自洽，不依赖任何跨块信息。 只要让 scale 与 payload 一起打包、一起流转即可（见 6.2）。 这是 C3 的直接满足。 MXFP8（每 32 元素）、
per-block 128×128
HiF8 + per-tensor ✅ 最省 HiF8 动态调整指数/尾数位，动态范围大， 因此可以用粗粒度 per-tensor 量化就维持 BF16 级训练精度， 从根上避免细粒度 scale 的元数据与归约开销。OSP-Next 走的就是这条路。 OSP-Next（NPU 侧）

这里有一个反直觉的判断

常规认知是「细粒度量化才保精度」，但在Ring 场景下： per-tensor 因为需要一个前置 all-reduce 而完全不可行； per-tile 是性价比最好的选择；而 HiF8 的「粗粒度 per-tensor」反而成了最优解—— 因为它用格式本身的动态范围换掉了「细粒度 scale 的归约与元数据开销」。

OSP-Next 的消融支持这一点：HiF8 训练的 loss 曲线与 BF16几乎重合， VBench 差距在 0.5% 以内。

6.2 per-tile scale 的通信成本（可以直接算掉）

# per-token-head scale（如 tile_size=128），N_kv=8, D=128, FP8 payload
payload = 128 · 8 · 128 · 1 = 131072 B
scale = 128 · 8 · 1 · 4 = 4096 B ⟹ ≈ 0.8%

# MX 规范：E8M0（1 byte）做 block-32 分组，同样量级
scale = 128 · 8 · (128/32) · 1 = 4096 B ⟹ ≈ 0.8%

# 最坏情形：FP4 payload + 32 元素块
payload = 65536 B, scale = 4096 B ⟹ ≈ 6.25%

结论：字节数不是问题，打包方式才是

scale 的额外通信量在 1%–6% 量级，不构成障碍。真正的损失来自两处：

  • 若 scale 与 payload 分两个 buffer、走两次 P2P， 就会多一次同步点与小包开销——在 Ring 的 P 个同步点上被放大。 这是必须避免的反模式。
  • 量化粒度若与环上块边界不对齐（例如 per-thread 量化， 粒度绑死在 mma 指令的线程↔内存映射上），跨 rank 传输时布局可能失真。 这再次说明 per-tile 因为与块边界对齐，最适合流转。

07量化在环上的四个断点

7.1 断点一：量化时机 —— 不能在环上反量化

这是最容易犯、代价最大的错误。正确的数据流是：块生成时量化，量化态一路走到 FA 内核。

✔ 正确：KV 块生成 → 块内量化 + scale → P2P（payload + scale）→ 量化 FA 消费

✘ 反模式：KV 块生成 → 量化 → 反量化回 FP16 → P2P（FP16）→ 再量化
代价：通信字节数退回 FP16，量化的收益全部丢失，还多付两次 cast

因为 Ring 的通信量本来就约为一次性拉取的 2 倍， 一旦退回 FP16，Ring 的通信劣势会被放大到不可接受。

7.2 断点二：量化必须作用在 K/V/P 上，绝不能作用在 softmax 统计量上

Ring 的正确性依赖 online softmax 的重缩放因子 exp(m_prev − m_new)，它有两个危险特性：

  • 当新块含极大值（m_new ≫ m_prev）时，因子趋近 0—— 之前累积的 O 几乎被完全丢弃。数学上正确，但在低精度下 O_prev 已经历多轮舍入，被放大回来时误差同步放大。
  • 作为量级参照：E4M3 的尾数只有 3 bit，相对误差量级约 6%，直接乘在部分输出 O 上。

昇腾把 ring_attention_update 的 softmax_max / softmax_sum 强制为 FLOAT32，这是正确的设计决策。 不要为了省显存把 softmax 统计量降到 BF16/FP16。

7.3 断点三：P 的量化会沿环累积误差

P（注意力概率）有一个好性质：它是每轮局部产生的，不需要跨 rank 流转—— 所以 P 的量化与 Ring 无接口冲突。

但它有一个坏性质：误差沿环累积。第 k 轮的 O_cur 由量化后的 P 与 V 相乘得到，在后续轮次中被反复重缩放并累加。 环上迭代次数 = P，所以累积路径长度随并行度增加。

这是一个「并行度 → 精度」的隐性耦合：同一模型 P=8 的精度可能差于 P=1。 验收必须按 P 扫描（P ∈ {1,2,4,8}）， 不能只在单卡验证量化精度然后假定 P=8 一样。

7.4 断点四：平滑统计量的全局性

SageAttention 的核心技巧是 smooth K：γ(K) = K − mean(K)， 其中 mean(K) 是全序列 token 的通道均值（消除 K 的 channel-wise outlier）。 SageAttention2 又加了 smooth Q，其统计量同样是全张量均值。

这与 per-tensor amax 有完全相同的问题：在 Ring 下要复现与单卡一致的量化结果， mean(K) 必须先在环上归约——又一次触碰 C2。

两条出路：

  1. 做一次环上归约：mean(K) 只有 D 维（如 128 个 float）， 通信量可忽略，主要代价是多一个同步点。 只要把它与 KV 块的首次量化放在同一阶段、只做一次（而不是每轮），代价可控。
  2. 改用块级局部平滑：完全去掉跨块依赖，与 Ring 天然兼容； 但可能丢失跨块的 outlier 结构，精度影响未知。

这个 trade-off 在公开文献中没有任何实验——SageAttention / SageAttention2 都是单卡 kernel 论文， 均未讨论 context parallel。属于确证的空白。

7.5 一个必须警惕的反面数据

08负载均衡：不均衡真的存在吗

对 Ring 路线的三个判断

  1. Ring 的 ρ_s 系统性低于 Ulysses（1.255–1.269 vs 1.355–1.447）。 原因：Ulysses 沿 head 切分，而稀疏度恰恰是逐 head 差异最大的量， 差异被直接放大到 rank 级；Ring 沿序列/块切分，把头间差异摊薄了。 这是选择 Ring 时一个额外的、独立的收益。
  2. 但 1.26 仍意味着约 21% 的潜在加速被浪费，不能忽略。
  3. 越激进的稀疏，不均衡越严重（PAROAttention 1.26 → SpargeAttn 未实现 Ring 版）。 如果用高稀疏率换性能，必须同步准备均衡机制。

8.2 两个层次的均衡，别混淆

db-SP：提前均衡（静态划分）

把耦合的头级/块级问题解耦，用「每个层级都能独立接近完美均衡」这个先验， 拆成两个顺序子问题，各自贪心。

开销抑制的关键：利用稀疏掩码在去噪步之间的相似性， 设阈值 P_s，低于阈值就复用上一步的划分计划。 动态稀疏下划分执行次数 = 层数 × 去噪步数，在 Wan2.1-T2V-14B 上高达 约 2000 次——复用是把这份开销压到可忽略的关键。

它的前提是「跨步相似」，这在多步采样（如 50 步）下成立得很好。

结果：端到端 1.25×、attention 1.40×。

FVAttn：运行时修复

出发点是硬观测：4 步蒸馏下，相邻步同一 head 的密度变化最高 97%、同一 rank 负载变化最高 44%。 预布局在用过期信号做决策。

做法：等掩码 materialize 后，按已实现的 per-head 负载， 用受限 P2P 迁移少量重头 head（8 卡下每 rank ≤ 1 个，约 20% 本地 head）， 把不均衡从 1.34 压到 1.08；再用 SASA 把非关键 rank 的残余空隙 兑换成额外的高价值块（不抬高全局阈值，因此不延长关键路径）。

但它的调度单元在 Ring 上不存在（见 3.2 障碍二）—— Ring 下每个 rank 只有一段 Q，没有「完整的 head」可搬运。

那么在 Ring 上该怎么做均衡？

FVAttn 的思路需要改造。Ring 下可搬运的单元不是 head，而是「块」—— 但如 3.3 障碍三所述，沿环预取远距离块的代价 ∝ 跳数。

所以 Ring 上的均衡手段应当按代价排序：

  1. 优先：从掩码设计上消除不均衡（路线 A，第 5.1 节）—— 规则化稀疏的子序列等长，逐轮均衡是结构保证的，零运行时开销。
  2. 其次：调整 Q 块到 rank 的映射（而非搬运 K 块）—— Q 本来就在本地，重新分配 Q 块只需要一次轻量的序列重排， 不涉及 K 的环上搬运。这是 FVAttn「搬 head」思路在 Ring 上的正确对应物。
  3. 最后：逐轮微调块的计算顺序——在 C1 允许的范围内调整， 但收益有限，因为每轮同步点仍然存在。

第 2 条是本文的推断，未见公开实现。但它抓住了关键： Ring 下「搬 Q」比「搬 K」便宜得多，因为 Q 不参与环上流转。

三个落地前必须实测的点

  1. RingAttentionUpdate 的 workspace 上限。 TND 布局下约束为 align64(N·D)·(dtype·6+8) + align64(N·8)·56 ≤ 196608 字节。 按 fp16 近似推算，D=128 时 N 上界约 65、D=256 时约 33—— 常见的 N=64/D=256 组合可能被直接拦截。 （按公式推算，实际含对齐取整会更紧，务必用最小用例实测。）

  3. softmax 统计量的显存膨胀。 它以 8 个重复值存储（[B,N,S,8]）， B=8, N=128, S=100K 时约 400 MB（fp32）。 这笔开销在 Ring 路径下容易被忽略——因为你会以为「KV 已经切到 1/P 了」—— 必须单列进显存预算。
