## 2. 业务背景与问题定义

视频生成模型的注意力计算具有序列长、访存量大、计算开销高的特点。BF16/FP16 Flash Attention 虽可减少中间张量，但在大规模部署中仍受显存容量、显存带宽和算力成本制约。业务需要在昇腾平台引入 MXFP4 低比特注意力，同时保证算子精度、不同 Q/KV 分块布局的泛化能力，以及模型部署端的完整接入。

现有链路缺少三个相互依赖的能力：MXFP4 Quant Flash Attention 核心算子、生成量化描述信息的 Metadata 算子、以及模型量化/推理模块对新算子的调用和参数管理。仅实现单一 Kernel 无法形成可商用闭环。

## 3. 需求范围

### 3.1 功能需求

1. 提供 Quant Flash Attention 与 Quant Flash Attention Metadata 两类算子。
2. 支持 MXFP4 数据组织、反量化尺度及注意力计算所需元数据生成。
3. 支持 qs128/kvs32 与 qs128/kvs256 Softmax 变体。
4. 在 MindIE-SD 量化模块中接入 MXFP4 FA，打通配置、权重处理、算子调用及输出路径。
5. 提供 Golden/UT 和模型端到端验证入口。

### 3.2 非功能需求

- 精度：单算子输出需与 Golden 参考结果满足项目精度门限；模型端输出不得出现不可接受的质量退化。
- 性能：低比特方案应减少注意力链路的数据搬运与计算开销，不引入明显的 Python 调度瓶颈。
- 兼容性：覆盖目标昇腾架构与 CANN 工具链，兼容多种 Q/KV 分块布局。
- 可靠性：非法 shape、dtype、布局和元数据应尽早失败，避免静默精度错误。
- 可维护性：算子实现、Metadata 处理、Python 部署接入和测试分层解耦。

## 4. 用例与依赖分析

核心参与者包括模型部署开发者、量化工具、MindIE-SD 推理框架和昇腾算子运行时。主流程为：读取量化模型与配置，生成/加载 MXFP4 权重和 Metadata，选择与布局匹配的 QFA Kernel，执行量化注意力并返回上层模型。

关键依赖包括 CANN 编译工具链、AICPU Metadata 执行能力、PyTorch/MindIE-SD 自定义算子注册机制及模型量化配置。需求交付必须同时覆盖算子侧和框架接入侧。

## 6. 风险与约束

低比特误差可能在长序列和多层网络中累积；不同布局的边界处理容易造成越界或静默数值错误；算子性能依赖目标硬件、shape 和工具链版本。验收时必须保留具体环境与阈值，不能将单一模型结果泛化为所有场景结论。
