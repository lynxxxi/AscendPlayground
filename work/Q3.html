01 / 10

先看结论

2026 年的分水岭不是分辨率，而是模型能否在动作闭环中，以可承受的延迟和显存维持状态、身份、几何与物理一致性。

Architecture

DiT 仍是底座，因果化成为出口

双向时空注意力保证短片质量；因果、分块自回归与 diffusion forcing / self forcing 把它改造成可持续输出的生成器。

Embodiment

世界模型的门槛是动作，不是画面

具身场景要求 action-conditioned、多视角一致、可反事实回放，并能与真实策略评测相关；纯 T2V 只能提供视觉先验。

Systems

瓶颈从 FLOPs 转向状态内存

流式推理中 KV cache 随历史增长。滚动窗口、语义检索、头级剪枝和低比特 KV 将决定分钟级生成是否可部署。

Training

后训练正在替代“从头训实时模型”

少步蒸馏、对抗后训练、自生成轨迹训练和模型合并，能把高质量双向教师迁移为低延迟因果学生，成本更可控。

Strategy

最优工程路线是分层，而非单模型通吃

高质量离线生成、快速预览、交互 rollout 与具身仿真有不同目标函数；共享 tokenizer / backbone，分开后训练与服务配置。

具身智能 × 世界模型

世界模型只有进入“观察 → 动作 → 未来 → 评价 / 再规划”闭环，才从视频生成器变成智能体基础设施。

Path A

生成式仿真环境

以 Genie 3 为代表，目标是从文本或图像即时生成可导航环境。优势是场景多样性与反事实事件，适合开放式课程学习；难点是动作可达性、长期状态和多智能体交互。

  • 实时视觉反馈，而非离线批量视频
  • 从键鼠动作扩展到连续控制
  • 智能体成功率成为核心指标
Path B

物理未来预测器

以 Cosmos、Qwen-RobotWorld、OSCAR 为代表，目标是在真实观测和动作条件下预测未来。优势是可服务机器人与驾驶数据增强、规划和策略筛选；难点是因果真实性与 sim-to-real 偏差。

  • 动作条件精度高于纯文本对齐
  • 多相机几何一致与接触动力学
  • 虚拟评测必须关联真实成功率
关键判断： 未来更可能出现“通用视觉世界先验 + 领域动作适配器 + 显式几何 / 状态约束”的组合，而不是一个纯像素模型直接覆盖所有机器人本体。OSCAR 的骨架条件与 Cosmos 的领域多视角模型都在释放这一信号。
2026 新信号： FLUX.3 把内容生成和动作预测放回同一 Self-Flow backbone，Tripo H3.1 则提供显式 Mesh/PBR 资产。前者可学习动力学表征，后者可提供可编辑几何；将两者通过仿真引擎组合，比要求一个像素世界模型同时承担几何真值、渲染与控制更务实。
06 / 10

长视频 / 流式生成

长视频不是把窗口拉长：窗口内要保持画质，窗口间要携带状态，系统还要在固定延迟与固定显存下持续运行。

STEP 01

双向教师

先用高质量 DiT / Flow 模型建立视觉、运动和语义先验。

STEP 02

因果化

改为 frame / chunk-wise causal attention，让未来不再泄漏到过去。

STEP 03

自轨迹后训练

Self Forcing / AAPT 让模型看到自身误差，并通过整段目标纠偏。

STEP 04

有界记忆

滚动、压缩或检索 KV，在固定预算内保留近期运动与远期身份。

07 / 10

模型优化技术栈

按投入产出比排序：先减少 token 和采样步，再处理注意力与缓存，最后才是底层 kernel。点击展开每一层。

L1

时空 Tokenizer / VAE

技术：causal 3D convolution、高空间 / 时间压缩率、分块编码解码、连续 latent 或 FSQ / VQ。视频 token 数下降会同时降低主干 FLOPs、注意力显存与 KV 体积。

注意：压缩率不能只看重建 PSNR；高速运动、文字、细小机械接触会首先损失。具身任务需加入 action-sensitive reconstruction 与多视角一致性指标。

L2

少步采样与后训练

技术：consistency / distribution matching distillation、adversarial post-training、flow trajectory distillation、模型合并、RL 后训练。目标从 30–50 NFE 压到 1–8 NFE。

注意：少步模型容易牺牲多样性和复杂运动。应分别测 prompt alignment、动态程度、失败率与长 rollout 稳定性，而非只看平均 VBench。

L3

因果 / 稀疏时空注意力

技术：frame / chunk causal mask、sliding tile、block sparse、局部窗口 + 稀疏全局 token、时空分解、pyramid attention broadcast。

注意：稀疏模式要对应信息结构：局部头负责纹理与运动，少量全局或检索头负责主体、场景和剧情；统一裁剪通常损害长时一致性。

L4

KV Cache 生命周期

技术：rolling KV 固定窗口、跨 chunk cache sharing、静态头结构化剪枝、动态头相似度剪枝、INT8 / INT4 量化、内容感知历史检索。

前沿：Forcing-KV 报告单 H200 超过 29 FPS、缓存下降 30%；这是论文硬件口径，不应直接外推到其他加速器或分辨率。

L4+

扩散 Timestep Feature Cache

不要与 KV cache 混淆：CacheDiT、TeaCache、First-Block-Cache 等利用相邻去噪 timestep 的 Transformer residual / feature 冗余，跳过部分 block 计算；AR KV cache 则保存历史帧注意力状态。

落地：CacheDiT 可组合 DBCache、TaylorSeer、SCM、并行和量化，并已接入 Diffusers、vLLM-Omni 与 SGLang Diffusion。它官方声明支持 Ascend NPU，适合先做低侵入 A/B，再评估长视频误差累积。

L5

并行策略

技术：Ulysses / Ring 序列并行、context parallel、CFG parallel、流水并行、VAE 与 DiT 异步重叠。xDiT 的 USP 已被 HunyuanVideo 等采用。

决策：短片通常通信成本敏感；长序列才充分受益。需要按分辨率 × 帧数 × 卡数扫描，而不是固定一个并行度。

L5+

MoE 与分阶段 Refiner

案例：MAGI-2 用 114B MagiMoE 保持容量、每 token 仅激活约 6B；先在 512×896 latent 上完成主体生成，再由独立 refiner 提升到 1088×1920，并用 Turbo VAE 解码。

系统重点：专家路由与 All-to-All、preview/refiner 分阶段调度、text encoder 与 VAE 的 CPU/GPU/roundtrip 卸载。当前 100+5 NFE 表明首要优化仍是蒸馏，其次才是 kernel。

L6

低精度与算子融合

技术：BF16 基线，权重 FP8 / INT8、KV INT8 / INT4、混合精度敏感层保留；融合 QKV、RoPE、norm、MLP、attention 与反量化。

注意：视频的误差会跨帧传播。量化校准集必须包含高速运动、镜头切换、长 rollout 和多视角，不应沿用静态图像校准集。

L7

数据与课程学习

技术：质量 / 运动 / 美学 / caption 分层，图像视频联合训练，低分辨率到高分辨率、短到长、通用到领域的 progressive curriculum。

具身扩展：统一动作语言、骨架 / 轨迹表示、多视角时间同步、失败轨迹与接触事件采样，其价值常高于盲目扩参。

L8

测试时计算与闭环选择

技术：多候选 rollout + VLM / reward rerank、风险敏感采样、物理约束 verifier、规划时短视界树搜索。世界模型可用更多 test-time compute 换取预测质量。

注意：生成分数更高不代表策略收益更高。最终选择器应优化任务成功、碰撞率、轨迹可执行性和校准误差。

08 / 10

评测与风险

当前榜单对短片视觉质量覆盖较好，但对长时记忆、交互延迟、动作因果和真实策略收益覆盖不足。

Measure

建议的四层指标

  • 帧级：清晰度、重建、文字 / 小物体
  • 片段级：运动、身份、镜头与语义一致
  • 系统级：首帧延迟、稳态 FPS、峰值显存、能耗
  • 闭环级：动作遵循、成功率、碰撞、真实相关性
Beware

常见误判

  • 把厂商自评 FPS 当跨硬件可比指标
  • 把“无限生成”当“无限记忆”
  • 用 VBench 替代物理与控制评测
  • 忽略闭源预览与开放权重的复现差异
证据纪律： 本报告中的 FPS、分辨率、显存和数据规模均保留原始来源语境，属于作者 / 机构报告值，除非特别说明并非独立复测。模型版本、许可证和仓库状态在 2026-08-11 后可能变化。
09 / 10

Ascend 验证路线

建议从可测量的三阶段原型开始：先跑通代表底座，再做缓存与少步优化，最后进入动作条件闭环。

框架基线

优先移植 minWM 的 Wan2.1-1.3B 路线，保留四阶段 checkpoint，建立 BF16 单卡与多卡基线。

  • 复用 LeRobotDataset 对齐观测 / 动作 / 相机
  • 固定 480p、短 / 长两组 rollout
  • 记录 NFE、首帧延迟、FPS、峰值 HBM

优化组合

按“4-step DMD → timestep cache / KV → 注意力 → 量化 → 融合”逐层消融，并与 FastVideo、TurboWan、CacheDiT、xDiT 路线对照。

  • 分开测试 feature cache 与 rolling KV
  • BF16 / FP8 权重 + INT8 KV 敏感性
  • USP/SP 拓扑、通信占比与 vLLM-Omni 服务开销

VLA × WM 闭环

用 Qwen-VLA / openpi 风格的 Action Expert 产生候选动作，让 minWM rollout 服务策略筛选。

  • 第三视角 + 腕部相机双视角
  • 短视界多候选 + reward / verifier
  • 虚拟排名与真实成功率相关性
