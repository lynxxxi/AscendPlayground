00 / DESIGN VERDICT
推荐结论

做一个薄 Facade，下面是一套重 Runtime

公开接口只描述张量语义、并行拓扑和质量约束；所有切分、collective、量化格式、stream/event、FA kernel 选择都由运行时生成不可变执行计划。上游不感知 HCCL 细节，也不复制模型仓里的 rank 表和环境变量分支。

prepare(spec, groups) → USPPlan，forward(plan, q, k, v) → output。先规划、后执行；一次校验，跨 DiT block 与 diffusion step 复用。

这个边界同时覆盖普通 FA、量化 FA、Ulysses、Ring、Hybrid USP、非等长序列、通信量化与通算重叠，并允许按能力降级。

2
个稳定核心调用
零个新增上游 backend

推荐：能力驱动 Runtime

统一 plan、buffer、collective 与 kernel；上游只传 tensor 和 process group。演进成本最低，最适合做出超越上游的组合优化。

备选：环境变量 Facade

快速兼容现有模型，但参数无类型、无法预检、难做逐层策略和可观测降级；仅作为一版迁移桥。

不选：两框架各自复制

短期改动小，长期产生两套通信/量化/FA 分支，性能补丁难同步，也无法稳定复用模型仓成果。

02 / ARCHITECTURE
控制面与数据面分离

上游交语义，MindIE-SD 交性能

控制面在初始化阶段完成能力探测、拓扑建组、shape/精度校验与 cost-based 选路；数据面只执行 plan，避免每个 diffusion step 重做 Python 判断。

03 / PUBLIC CONTRACT
最小稳定接口

配置可读，计划不可变，热路径无分支

公开类型不出现 HunyuanVideo、Omni、SGLang、A5 等模型或框架名字；设备差异留在 capability 和 planner 内。框架可以把 plan 缓存到 attention layer 实例。

@dataclass(frozen=True)
class AttentionSpec:
    layout: Literal["BSND", "BNSD"]
    batch: int
    q_heads: int
    kv_heads: int
    head_dim: int
    q_dtype: torch.dtype
    out_dtype: torch.dtype
    sequence: SequenceMeta
    causal: bool = False

@dataclass(frozen=True)
class ProcessGroups:
    ulysses: object | None = None
    ring: object | None = None

class USPRuntime:
    @classmethod
    def capabilities(cls) -> USPCapabilities: ...

    def prepare(self, spec: AttentionSpec,
                groups: ProcessGroups) -> USPPlan: ...

    def forward(self, plan: USPPlan, q: torch.Tensor,
                k: torch.Tensor, v: torch.Tensor,
                *, joint_k=None, joint_v=None,
                attn_mask=None) -> torch.Tensor: ...

    def explain(self, plan: USPPlan) -> Mapping[str, object]: ...

04 / EXECUTION PLAN
三条核心执行路径

同一接口，不同拓扑生成不同 DAG

切换下面的路径查看 planner 产物。通信量化不是独立后处理，而是 collective 的 codec；FA 不是上游枚举，而是 plan 中的 compute node。

01 · FUSED PACK

Q/K/V 一次布局变换并合包，减少三个 Python collective 和临时 tensor。

02 · QUANT A2A

按策略量化通信 payload；scale 同步走伴随 buffer，异步 all-to-all。

03 · RING KV GATHER

K/V 以 FP8/MXFP8 聚合；按真实长度 trim，dequant 延迟到 FA。

04 · QUANT FA

Q 局部量化，融合消费 K/V quant data + scale，避免 BF16 回写。

05 · REVERSE A2A

输出按原 sequence shard 归位；可与下一 chunk 的 FA 重叠。

06 · DOUBLE BUFFER

comm stream / compute stream 通过 event DAG 交接，无全局 synchronize。

07 · TRIM

移除 padding，恢复框架 layout 与 dtype。

08 · TELEMETRY

记录 bytes、comm exposed time、kernel 与 fallback，归因可见。

01 · PACK QKV

Q/K/V 统一 reshape/transpose，优先使用单个连续 workspace。

02 · ALL-TO-ALL

head shard → sequence shard；支持 BF16 与量化 payload。

03 · JOINT KV

按 rank 只切 joint K/V head，不复制模型私有分支。

04 · FA

选择 native FA 或 quant FA，保持输入输出语义一致。

05 · PIPELINED RETURN

chunk FA 与上一 chunk reverse A2A 交叠。

06 · RESTORE

恢复原 head/sequence 布局，返回上游 output projection。

01 · PROBE FAIL

缺少 operator、shape 不支持、误差门不通过或 profile 无收益。

02 · DOWNGRADE QUANT

quant collective → BF16 collective，保留并行语义。

03 · DOWNGRADE FA

quant FA → native FA → upstream SDPA，逐级明确。

04 · REPORT

一次 warning + 结构化 reason；禁止 silent fallback。

比模型仓更快：少发

优先合包 QKV、复用 buffer、减少 launch 与 Python dispatch；K/V 量化后通信，理论 payload 由 BF16 的 2B/elem 降至约 1B/elem + scale。

比上游更快：藏住

把量化、collective、FA 和 reverse collective 排成跨 chunk DAG，以 exposed communication time 而非 collective 总时间为优化目标。

比手工开关更稳：会选

使用 shape/topology capability 和微型 profile 选 plan；小序列或单卡不强开复杂路径。

06 / PERFORMANCE CONTRACT
不能只说“更快”

把超越上游写成合入门槛

所有数字是验收目标，不是当前实测结论。基线必须使用同一 commit、CANN、MindIE、卡型、输入、seed、warmup 与质量门，分别对比上游 native、模型仓最佳手工配置和 USP plan。

≥ 1.15×4 卡 DENOISE 吞吐

960×960×61、固定 50 steps，对比上游最佳 NPU 路径。

≥ 1.20×8 卡 DENOISE 吞吐

收益必须来自 exposed comm 降低，而非减少 step 或变更输出。

≤ 0.70×暴露通信时间

以 profiler critical path 中未被 compute 覆盖的通信为准。

≤ 1%质量绝对退化

由模型团队冻结 VBench 子指标/任务阈值；超限自动禁用通信量化。

层级基准对象必须采集合入条件
MicroA2A、AllGather、quant/dequant、FAGB/s、launch、workspace、kernel time量化后有效带宽收益覆盖 codec 开销
Block单个 double/single stream DiT blockcritical path、event gap、临时显存无全局 sync；plan 结果可复现
Stage完整 denoise 50 stepsP50/P95、NPU 利用率、comm exposed4/8 卡达到目标且无 OOM
E2EText encoder + DiT + VAE首帧/总时延、峰值显存、质量不以其他 stage 回归换 DiT 指标
CompatibilityOmni / SGLang；1/2/4/8 卡路径命中、fallback reason、数值缺 MindIE 或不支持 shape 时仍正确运行
Benchmark 纪律：报告同时给出 plan.explain()、环境 fingerprint 与 profiler 证据；禁止只报“开关前后耗时”，否则无法区分 kernel、通信、缓存或测量噪声。
07 / ADR & FAILURE MODES
关键决策

性能接口也必须可失败、可维护

以下决策作为首版 ADR 固化；它们约束模块边界，不固化具体 operator 名称。

ADR-001 · Plan-first

决定：初始化生成不可变 plan，forward 不做策略判断。
代价：动态 shape 必须声明范围或重新 prepare。
原因：可缓存、可图捕获、可解释。

ADR-002 · Quant is codec

决定：通信量化属于 collective codec，而非 attention 单独前处理。
代价：需要 scale protocol 与 HCCL buffer 管理。
原因：才能融合和延迟 dequant。

ADR-003 · Keep backend names

决定：不在上游增加 MindIE USP backend。
代价：接入点是平台私有方法。
原因：用户配置稳定，供应商实现可替换。

01

通信量化误差放大

按层/step 质量 gate；支持仅 K/V 量化、敏感 block allowlist、BF16 fallback，并将策略写入 plan hash。

02

重叠反而变慢

小序列或低并行度关闭 chunk pipeline；warmup profile 比较 overlap on/off，收益未过阈值不启用。

03

group / rank 错配导致 hang

prepare 阶段 all-rank 交换 topology fingerprint；不一致立即失败，不进入 collective。

04

上游升级导致私有接口漂移

adapter 极薄、按框架版本做 contract test；MindIE 核心只依赖 tensor/spec/groups，不 import 上游包。

05

非等长序列越界或 silent trim

SequenceMeta 保存原始/填充长度与 cu_seqlens；debug 模式校验每 rank checksum。

06

workspace 峰值抵消收益

plan 输出显存预算；buffer pool 复用，超过预算时降 chunk、关重叠或退回 native。
