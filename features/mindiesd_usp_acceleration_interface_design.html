00 / DESIGN VERDICT
推荐结论

像 FlashInfer 的单算子接口，不做 plan 服务

公开接口接收 Q/K/V、并行元数据、通信量化选项和可选 workspace，在一个调用中完成布局变换、collective、量化 FA 与输出恢复。上游负责生成并行方案；MindIE-SD 不提供 planner、cost model 或 prepare()。

usp_attention(q, k, v, *, meta, options, workspace=None, out=None) → output。一个入口、一次执行、没有公开 plan 生命周期。

与 FlashInfer 的单请求 attention 一样，数据、布局、scale、backend 和可选输出缓冲都显式；复杂的 Ulysses/Ring 信息收进上游构造的 USPMetadata。

1
个稳定核心调用
零个 plan API

推荐：函数 + 显式元数据

最接近 FlashInfer 单请求 API。上游拥有决策权，MindIE-SD 拥有执行优化；接口没有隐藏的跨调用状态。

可选：调用方 workspace

需要固定地址、图捕获或零分配时显式传入 uint8 workspace；普通调用可使用 MindIE-SD 内部缓存池。

删除：prepare / USPPlan

不在加速库里重复实现上游调度器，也不要求 attention layer 维护第二套 plan 生命周期。

01 / FLASHINFER REFERENCE
参考，但不照抄

FlashInfer 有两类接口，USP 应选函数式这一类

FlashInfer 的 API 边界取决于调用是否需要跨 kernel 复用调度结构：单请求 prefill 是一个直接函数；批量 paged KV 才用持久 wrapper 和 plan/run。USP 的调度结构已经由上游框架产生，因此更接近前者。

FlashInfer 形态典型接口为什么这样设计对 MindIE-SD USP 的结论
单请求函数single_prefill_with_kv_cache(q, k, v, ..., backend="auto")输入语义完整；函数内部做 backend dispatch，直接返回 output / LSE采用：一个 usp_attention 调用
批量 wrapperBatchPrefillWithPagedKVCacheWrapper(workspace)需要复用 paged metadata、split-k 辅助结构和稳定 workspace只借鉴 workspace 所有权，不照搬公开 plan
量化参数scale_q / scale_k / scale_v / kv_cache_sf量化数据与 scale 显式配对，输出 dtype 显式采用：scale 与 comm codec 都是明确参数
backend 选择backend="auto" | "fa2" | "fa3"调用者可固定实现，也可按设备和 kernel 能力自动分发采用：backend="auto" | "npu_fa" | "quant_fa"
输出与 workspaceout=None；wrapper 绑定 caller-owned workspace兼顾易用路径与零分配/图捕获路径采用：out、workspace 都可选

学它的显式性

tensor、layout、mask、scale、output dtype、backend 都从函数签名可见；不靠全局环境变量改变语义。

学它的资源所有权

高性能调用允许调用方提供 output 和 workspace，避免热路径分配并支持稳定地址。

不学它的 plan/run

FlashInfer 的 plan 服务于 batch paged KV 内部调度；USP 的并行调度归上游，复制这层会职责重叠。

03 / ARCHITECTURE
决策面归上游，执行面归加速库

上游交完整执行描述，MindIE-SD 交性能

vLLM-Omni / SGLang MM 负责并行模式、process group、切分维度、chunk 和 fallback；MindIE-SD 只校验调用契约，并按这些明确参数执行 NPU 热路径。没有第二套控制面。

UPSTREAM DECISION OWNER

vLLM-Omni / SGLang MM

现有 FlashAttentionImpl / AscendFAImpl 生成 USPMetadata，持有 process group、序列切分和 fallback 生命周期。

→
SINGLE PUBLIC OP

mindiesd.usp_attention

显式接收 tensor、metadata、options、scale、workspace 与 out；成功返回 output，不支持则抛结构化异常。

→
OPTIMIZED EXECUTOR

Comm · Quant · FA

只实现合包、collective codec、stream/event、workspace 和 FA kernel dispatch；不生成上游并行方案。

INPUTq / k / v / joint kv / mask
VALIDATEshape / group / layout / codec
WORKSPACEcaller buffer or internal pool
PACKlayout transform / qkv fusion
COMMquantize / collective / overlap
FAnative / quant backend dispatch
OUTPUTreverse A2A / trim / out

Functional API

一个稳定 Python 函数；语义由参数决定，不由对象隐式状态或环境变量决定。

Typed Metadata

上游把 Ulysses/Ring group、切分维度、真实长度和 chunk 变成强类型数据。

Executor

复用 buffer、async collective、event 依赖和图捕获；数据面不动态 import。

Strict Failure

不支持就抛 USPNotSupported；fallback 由现有上游 backend 统一处理。

04 / PUBLIC CONTRACT
最小稳定接口

一个函数，元数据由上游构造

公开类型不出现 HunyuanVideo、Omni、SGLang、A5 等模型或框架名字。USPMetadata 只是执行描述，不是 MindIE-SD 生成的 plan；它可由上游 attention backend 直接从已有 parallel state 构造。

from dataclasses import dataclass
from typing import Literal
import torch

@dataclass(frozen=True)
class CommSpec:
    dtype: Literal["none", "fp8_e4m3", "mxfp8"] = "none"
    tensors: tuple[str, ...] = ("k", "v")

    kv_block_size: int = 256
    scale_dtype: torch.dtype = torch.float32

class USPMetadata:
    mode: Literal["ulysses", "ring", "hybrid"]
    ulysses_group: object | None
    ring_group: object | None
    scatter_dim: int = 2
    gather_dim: int = 1
    seq_lens: torch.Tensor | None = None
    chunk_size: int | None = None

@dataclass(frozen=True)
class USPOptions:
    layout: Literal["BSND", "BNSD"] = "BSND"
    comm: CommSpec = CommSpec()
    overlap: bool = False

def usp_attention(

    joint_v: torch.Tensor | None = None,
    attn_mask: torch.Tensor | None = None,
    q_scale: torch.Tensor | None = None,
    k_scale: torch.Tensor | None = None,
    v_scale: torch.Tensor | None = None,

    return_lse: bool = False,
) -> torch.Tensor | tuple[torch.Tensor, torch.Tensor]: ...
参数组谁提供MindIE-SD 做什么错误行为
并行 metadata上游提供 mode、groups、scatter/gather dim、seq_lens、chunk只校验 group/world size/head 可分并执行USPTopologyError
tensor 语义上游提供 Q/K/V、layout、joint KV、mask、out dtype布局转换、padding/trim 与输出恢复USPShapeError
量化与 scale上游选 comm codec；已有量化 tensor 时显式给 scale执行 quant collective 与 FA 直读USPNotSupported，不静默回退
workspace / out上游可提供稳定 buffer；也可留空走缓存池检查容量与对齐，避免热路径临时分配USPWorkspaceError
兼容旧环境变量：映射逻辑放在模型/框架 adapter，不放入 mindiesd.usp。新接口从第一版开始就只有显式参数，避免环境变量成为长期 ABI。
05 / EXECUTION PATH
三条核心热路径

同一调用，按上游 metadata 直接执行

切换下面的路径查看 executor 如何消费 USPMetadata。通信量化是 collective 的 codec；FA backend 仅做 kernel dispatch，不替上游决定并行方案。

01 · FUSED PACK

Q/K/V 一次布局变换并合包，减少三个 Python collective 和临时 tensor。

02 · QUANT A2A

按策略量化通信 payload；scale 同步走伴随 buffer，异步 all-to-all。

03 · RING KV GATHER

K/V 以 FP8/MXFP8 聚合；按真实长度 trim，dequant 延迟到 FA。

04 · QUANT FA

Q 局部量化，融合消费 K/V quant data + scale，避免 BF16 回写。

05 · REVERSE A2A

输出按原 sequence shard 归位；可与下一 chunk 的 FA 重叠。

06 · DOUBLE BUFFER

comm stream / compute stream 通过 event DAG 交接，无全局 synchronize。

07 · TRIM

移除 padding，恢复框架 layout 与 dtype。

08 · TELEMETRY

记录 bytes、comm exposed time、kernel 与 fallback，归因可见。

01 · PACK QKV

Q/K/V 统一 reshape/transpose，优先使用单个连续 workspace。

02 · ALL-TO-ALL

head shard → sequence shard；支持 BF16 与量化 payload。

03 · JOINT KV

按 rank 只切 joint K/V head，不复制模型私有分支。

04 · FA

选择 native FA 或 quant FA，保持输入输出语义一致。

05 · PIPELINED RETURN

chunk FA 与上一 chunk reverse A2A 交叠。

06 · RESTORE

恢复原 head/sequence 布局，返回上游 output projection。

01 · VALIDATE

在首个 collective 前检查 shape、layout、group、workspace 与 backend 能力。

02 · RAISE

不支持时抛出 USPNotSupported 或细分契约异常，不在库内静默改策略。

03 · UPSTREAM FALLBACK

vLLM-Omni / SGLang MM adapter 捕获异常并调用各自现有 native FA 路径。

04 · REPORT

一次 warning + 结构化 reason，记录未命中的 dtype、shape 或 operator。

比模型仓更快：少发

优先合包 QKV、复用 buffer、减少 launch 与 Python dispatch；K/V 量化后通信，理论 payload 由 BF16 的 2B/elem 降至约 1B/elem + scale。

比上游更快：藏住

把量化、collective、FA 和 reverse collective 排成跨 chunk DAG，以 exposed communication time 而非 collective 总时间为优化目标。

比手工拼装更稳：契约明确

上游负责判断小序列、单卡和 overlap 是否值得启用；MindIE-SD 只验证声明与实际 tensor/group 一致并稳定执行。

07 / PERFORMANCE CONTRACT
不能只说“更快”

把超越上游写成合入门槛

所有数字是验收目标，不是当前实测结论。基线必须使用同一 commit、CANN、MindIE、卡型、输入、seed、warmup 与质量门，分别对比上游 native、模型仓最佳手工配置和 usp_attention。

≥ 1.15×4 卡 DENOISE 吞吐

960×960×61、固定 50 steps，对比上游最佳 NPU 路径。

≥ 1.20×8 卡 DENOISE 吞吐

收益必须来自 exposed comm 降低，而非减少 step 或变更输出。

≤ 0.70×暴露通信时间

以 profiler critical path 中未被 compute 覆盖的通信为准。

≤ 1%质量绝对退化

由模型团队冻结 VBench 子指标/任务阈值；超限自动禁用通信量化。

层级基准对象必须采集合入条件
MicroA2A、AllGather、quant/dequant、FAGB/s、launch、workspace、kernel time量化后有效带宽收益覆盖 codec 开销
Block单个 double/single stream DiT blockcritical path、event gap、临时显存无全局 sync；同一 metadata 结果可复现
Stage完整 denoise 50 stepsP50/P95、NPU 利用率、comm exposed4/8 卡达到目标且无 OOM
E2EText encoder + DiT + VAE首帧/总时延、峰值显存、质量不以其他 stage 回归换 DiT 指标
CompatibilityOmni / SGLang；1/2/4/8 卡路径命中、fallback reason、数值缺 MindIE 或不支持 shape 时仍正确运行
Benchmark 纪律：报告同时给出 USPMetadata、USPOptions、实际 backend、workspace bytes、环境 fingerprint 与 profiler 证据；禁止只报“开关前后耗时”。
08 / ADR & FAILURE MODES
关键决策

性能接口也必须可失败、可维护

以下决策作为首版 ADR 固化；它们约束模块边界，不固化具体 operator 名称。

ADR-001 · Single-call

决定：不提供 prepare 或 plan API；上游传入执行 metadata，forward 单次完成。
代价：adapter 必须正确维护 metadata 与 workspace。
原因：避免重复调度器与第二套生命周期。

ADR-002 · Quant is codec

决定：通信量化属于 collective codec，而非 attention 单独前处理。
代价：需要 scale protocol 与 HCCL buffer 管理。
原因：才能融合和延迟 dequant。

ADR-003 · Keep backend names

决定：不在上游增加 MindIE USP backend。
代价：接入点是平台私有方法。
原因：用户配置稳定，供应商实现可替换。

01

通信量化误差放大

按层/step 质量 gate；支持仅 K/V 量化、敏感 block allowlist、BF16 fallback，并记录 metadata/options fingerprint。

02

重叠反而变慢

上游用 warmup/profile 决定小序列或低并行度是否关闭 pipeline，再通过 options.overlap 与 meta.chunk_size 明确传入。

03

group / rank 错配导致 hang

adapter 契约测试覆盖 rank 映射；单次调用在首个 collective 前校验 group、world size、head 可分性和本地 metadata。

04

上游升级导致私有接口漂移

adapter 极薄、按框架版本做 contract test；MindIE 核心只依赖 tensor/spec/groups，不 import 上游包。

05

非等长序列越界或 silent trim

USPMetadata.seq_lens 保存真实长度；debug 模式校验每 rank checksum，输出严格按原始长度 trim。

06

workspace 峰值抵消收益

调用方显式传入稳定 buffer 或使用内部有上限的缓存池；容量不足直接抛错，由上游决定降 chunk、关重叠或 native fallback。

09 / DELIVERY
分阶段落地

先统一语义，再吃掉通信热路径

每阶段都有独立退出条件，避免一次把量化、并行、FA、上游接入全部绑在同一个大补丁里。

PHASE 0 · CONTRACT

Single-call 与基线

冻结函数签名、metadata/options、异常与 workspace 契约；复刻模型仓 4/8 卡 BF16 路径，建立三方基线。

EXIT → 数值对齐；无性能回归；路径可观测
PHASE 1 · COMM CORE

统一 collective

拓扑建组、QKV pack、非等长切分、buffer pool、async handle；消除硬编码 rank 表。

EXIT → 2/4/8 卡稳定，无 hang / OOM
PHASE 2 · QUANT + OVERLAP

性能主战场

FP8/MXFP8 codec、scale protocol、quant FA 直读和双缓冲 event pipeline；开关与 chunk 由上游 options 给定。

EXIT → 达到 4/8 卡性能与质量门
PHASE 3 · UPSTREAM

两个薄适配

先 vLLM-Omni，再 SGLang MM；增加 feature detection、native fallback、契约测试与文档。

EXIT → 两框架同单次调用语义、同 profiler 口径
