长视频推理：
从“重算”到“增量”

长视频推理的核心，不是把短视频模型反复调用，而是让每个新 chunk 只计算新增内容，并把历史状态控制在有界预算内。主线是减少主干前向次数、消除历史重算、压缩缓存、重叠 DiT 与 VAE；Self-Forcing 等专门训练只负责提供能走这条快路的 checkpoint。

01 / THESIS

先给结论：长度只是表象，状态才是问题

“能生成 2 分钟”并不自动等于“理解了前 2 分钟”。长视频系统要同时解决误差累积、历史压缩、计算增长和叙事控制；任何只解决一项的方案，都可能得到很长但近乎静止、身份漂移或语义失忆的视频。

01 / NFE × RECOMPUTE

真正昂贵的是“多步 × 全段重算”

普通扩散每个 timestep 都重新执行 DiT；若延长窗口还要重复处理历史 token。少步 checkpoint 先减少主干调用，因果 KV 再让历史从“参与重算”变成“只读状态”。

02 / MEMORY BUDGET

无限输出 ≠ 无限记忆

FIFO 队列可以恒定显存地一直吐帧，但被淘汰的历史不再可见。主体离场后再出现、空间布局回忆和因果闭环，仍需要显式长期记忆。

03 / SYSTEM CO-DESIGN

算法与系统开始合流

少步蒸馏、因果注意力、KV cache、流式 VAE、量化和序列并行共同决定真实吞吐；只优化 DiT FLOPs 不足以得到实时系统。

推理优先级先砍 NFE，再砍历史重算；随后优化 attention kernel、量化、并行与异步 VAE。专门训练的作用是产出因果、少步、能承受自生成历史的 checkpoint，训练系统本身不属于本页分析主线。
02 / EXECUTION

普通视频 DiT 与长视频模型，差在推理怎么执行

两者都可能使用 VAE + Diffusion Transformer。普通模型对固定 clip 做多步联合去噪；前沿长视频模型按因果 chunk 增量执行，显式维护计算缓存与语义状态，让每块延迟和显存不随总时长失控。

ORDINARY VIDEO DIT

固定 clip 的联合去噪

  • 文本 / 首帧编码后，与整段 noisy video latent 共同输入 Video DiT。
  • 时间注意力通常双向：当前帧可以读取未来帧，适合整段质量，不适合边生成边提交。
  • 每个 timestep 重算整段 token；长度增长时 attention、激活和 VAE 解码成本一起增加。
  • 训练与推理都针对固定时长 clip，超出训练窗口主要依赖重叠拼接或位置外推。
CAUSAL LONG-VIDEO MODEL

按 chunk 增量执行

  • block-causal mask 把视频切成可提交的时间块；历史只读，新块负责产生未来。
  • 每层历史 K/V 可缓存，下一块只计算新 token；rolling window 让单步显存有界。
  • 少步 checkpoint把几十次前向压到 1–4 次，VAE 与下一块 DiT 可并行。
  • 模型必须提供因果 mask、状态读写和少步 scheduler 的稳定接口；如何训练出这些能力只作前置条件说明。

前沿流式模型的一次循环

01 / CONDITION预填充条件全局 prompt 编码尽量复用；chunk prompt 或动作只更新增量。
02 / CONTEXT读取历史状态rolling KV、首帧 sink、memory token 与时间位置。
03 / DENOISE少步 causal DiT只为新 chunk 预测 latent；未来块严格不可见。
04 / COMMIT提交并更新缓存新 K/V 写入；旧状态淘汰、压缩或合并进长期记忆。
05 / ASYNC VAE解码与编码当前 latent 转帧，并与下一 chunk 的 DiT 异步重叠。
06 / DEADLINE继续或降级按 TPC 预算动态调 NFE、分辨率、增强器与缓存窗口。

“记忆”至少有四层，KV 只覆盖其中一部分

L0 / PIXEL

局部运动连续

最近几帧 / latent 保持速度、光流和纹理衔接，生命周期最短。

L1 / COMPUTE

注意力 KV

避免历史 token 重投影；它是计算缓存，不天然等于可解释的世界记忆。

L2 / ENTITY

身份与空间状态

角色外观、物体关系、场景布局需要 memory token、检索或显式对象状态。

L3 / STORY

事件与叙事摘要

目标、因果、伏笔和 prompt 变化需要结构化摘要与规划器，当前模型仍很薄弱。

真正的结构差异普通模型优化的是“一个 clip 的联合样本质量”；长视频模型优化的是“状态更新算子在重复调用后是否仍稳定”。因此必须同时评测单块画质、chunk 边界、漂移曲线、缓存预算与长时语义，而不能只看首段 VBench。
03 / EVOLUTION

按推理执行方式看五次迁移

主线是窗口重算 → 分块流水 → 因果少步 → 有界状态 → 演化记忆；专门训练只标记哪些快路不能直接套在普通 checkpoint 上。

2022

Latent Video Diffusion

LATENTHIERARCHY

把视频生成搬到压缩潜空间，并用关键帧/插值式层级建模降低像素级成本。它奠定了后续 Video DiT 的工程底座，但“长”仍依赖层级结构和有限窗口。论文 ↗

2023

Gen-L-Video / FreeNoise

NO TRAININGWINDOW

第一代主流思路是“复用短视频模型”：Gen-L-Video 用重叠片段的 temporal co-denoising；FreeNoise 重排并复用初始噪声、采用窗口注意力。优势是零训练迁移，弱点是全局状态与新运动逐渐衰减。Gen-L ↗ · FreeNoise ↗

2024 H1

StreamingT2V / FIFO-Diffusion

CHUNK ARQUEUEMEMORY

StreamingT2V 为分块自回归显式加入短期 CAM 与首段外观长期记忆；FIFO-Diffusion 让不同噪声级帧在队列里对角去噪，以恒定内存持续出帧。此时“可扩展长度”形成，但误差闭环仍主要发生在推理期。StreamingT2V ↗ · FIFO ↗

2024 H2

Diffusion Forcing

CAUSALVARIABLE NOISE

推理时，每个时序 token 可处于独立噪声等级，使系统能在因果约束下连续展开，并灵活选择各位置的去噪进度。它需要专门训练的 checkpoint；部署风险仍是长 rollout 的误差累积。论文 ↗

2024→25

CausVid

CAUSAL DITDMD4 STEP

将慢速双向教师蒸馏为块因果学生，以 ODE 轨迹初始化和非对称分布匹配蒸馏稳定训练；4 步生成与 KV cache 带来论文报告的单卡 9.4 FPS。它证明高质量教师可以转化为快速流式模型。论文 ↗

2025.06

Self-Forcing

FEW STEPCAUSAL CHUNKROLLING KV

部署产物支持少步因果 chunk 与 rolling KV cache，新块不再重算全部历史，适合流式 deadline。为降低长时漂移，checkpoint 需要用自身生成历史做专门训练。论文 ↗

2025 H2

LongLive / Self-Forcing++

FRAME SINKKV RECACHELONG ROLLOUT

LongLive 的短窗 + frame sink 控制状态预算，KV recache 允许动态提示；Self-Forcing++ 进一步延长 checkpoint 可承受的推理时域，论文展示最长 4:15。二者都需要专门训练，但部署关注点是缓存策略、重算边界和稳态 FPS。LongLive ↗ · SF++ ↗

2026

压缩记忆 → 演化记忆

2-BIT KVMEMORY QUERYRELATIVE ROPE

Quant VideoGen 把 KV cache 压缩到 2-bit 级方案以换取更大有效上下文；Echo-Infinity 用可学习 Memory Query 持续吸收被淘汰历史，并修正 RoPE 外推。论文宣称 24 小时 rollout，但这应理解为持续生成与恒定成本的展示，不等同于 24 小时叙事推理。QVG ↗ · Echo ↗

04 / PREREQUISITE

为什么推理快路需要专门 checkpoint？

部署目标是“因果 chunk + 少步前向 + 滚动状态”。普通双向、多步 checkpoint 没有这些执行契约，不能只靠 runtime 开关强行获得。

ORDINARY CHECKPOINT · OFFLINE PATH

固定 clip，多步整段去噪

完整 noisy clip
↓ 双向 attention
每个 timestep 重算全段
↓ 多次主干前向
整段完成后统一解码
⚠
不保证跨 chunk 状态可复用
VS
SPECIALIZED CHECKPOINT · FAST PATH

增量 chunk，少步流式执行

条件与首块 prefill
↓ 读取 rolling KV
只计算新 chunk
↓ 1–4 次主干前向
提交状态并异步 VAE
↺
按 deadline 连续输出
01 / CAUSAL CONTRACT

checkpoint 必须适配 block-causal mask；否则把双向注意力临时改成因果 mask，通常会明显损伤质量。

02 / FEW-STEP CONTRACT

少步 scheduler 需要相应蒸馏权重。runtime 可以减少调用，却不能让普通 40–50 步模型凭空保持 4 步质量。

03 / STATE CONTRACT

层间 KV、latent、位置编码与随机状态要有稳定的读写格式，才能暂停、迁移、淘汰和跨块复用。

04 / DRIFT TOLERANCE

Self-Forcing / 长 rollout 等专门训练让模型更能承受自己的历史；部署侧仍需测逐 chunk 漂移并设置降级或刷新点。

训练边界因果适配、少步蒸馏和长 rollout 只需理解为“产出专用 checkpoint 的上游工作”。本页后续优化从可用权重开始，关注前向次数、缓存、kernel、量化、并行、调度与媒体流水。
05 / MATRIX

按推理成本横向对比

优先看一次输出要做多少主干前向、是否重算历史、状态是否有界；论文 FPS 来自不同硬件与口径，仅用于理解路线，不能直接排行。

06 / FRONTIER

接下来会演进到哪里

以下是基于现有论文路线作出的技术推断，而非已经兑现的产品能力。

Memory

从缓存帧到结构化世界状态

未来记忆不会只保存首帧或若干 KV，而会分层保存身份、几何、对象关系、事件摘要，并在需要时检索。Echo-Infinity 的可学习演化记忆是这一方向的早期形态。

Scheduler / Runtime

从固定参数到漂移感知的动态执行

推理引擎可按 chunk 的 deadline、运动强度和漂移指标动态调整 NFE、缓存窗口、状态刷新与增强器：稳定段走低成本快路，关键事件临时增步或回退高质量路径。

Architecture

局部精确 + 全局压缩的双时间尺度

短窗口负责纹理和运动连续，稀疏全局 token 或状态空间模块负责远期因果。全量历史 attention 不经济，纯 FIFO 又会遗忘，混合结构是更可能的平衡点。

System

KV、VAE 与低比特成为同等重要的主角

少步 DiT 已把去噪压到 1–4 步后，瓶颈转向 KV 容量、异步解码、通信和带宽。2-bit KV、FP4/W4A4、流式 VAE 与 cache-aware kernel 会决定能否真正落地。

它没有解决的事

  • 固定 rolling cache 仍会遗忘窗口外细节；对象长期遮挡后重现、房间空间关系和故事伏笔并无保证。
  • 自回滚能减小但不能消灭误差累积；基础短视频教师的偏差、动作模式与视觉先验仍会传给学生。
  • “实时”取决于 GPU、分辨率、帧率、VAE 是否计入和初帧延迟；论文间 FPS 不能直接横比。
  • 长视频评测仍偏弱。短片 VBench 得分、两分钟无硬切，不足以证明分钟级因果与叙事一致性。
08 / ASCEND

对 AscendPlayground 的实现启示

如果目标是把此类模型迁移到昇腾，优先级应围绕可验证的系统闭环，而不是一次性复刻全部论文技巧。

先跑通因果基线

实现 block-causal attention、chunk 级 rollout 与正确的 temporal RoPE；建立短视频质量基线与逐 chunk 漂移曲线。

再做 rolling KV

明确 sink/local window 淘汰策略，记录 cache 显存、搬运带宽与长程主体一致性；KV 格式先 FP16/BF16，再评估 INT8/FP8。

优先取得少步 checkpoint

部署先锁定可用的 1–4 步权重；训练/蒸馏放在上游完成。runtime 随后叠加 sparse attention、编译、量化和异步 VAE，并逐项隔离收益。

按时间轴验收

固定 prompt/seed，每 5–10 秒记录身份、布局、运动、提示遵循和帧率；同时报告首帧延迟、稳态 FPS 与完整 E2E。
